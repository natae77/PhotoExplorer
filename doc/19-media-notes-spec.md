# 19. 미디어 메모 기능 기획서

사진과 동영상에 짧은 메모를 남기고, **MEDIA 폴더 화면**과 **전체 화면 미디어 뷰어**에서만
메모의 존재와 내용을 확인·편집할 수 있게 한다.

이 문서는 *무엇을 만들 것인가*를 정의한다. 구현 방법과 작업 순서는 구현 계획을 세울 때
별도로 구체화한다.

- 작성일: 2026-09-15
- 프로젝트: **PhotoExplorer** (`zhanghai/MaterialFiles` fork)
- 상태: **초안**

## 1. 배경

스윙 영상이나 연속 사진을 검토할 때 사용자는 "백스윙이 빠름", "7번 아이언", "다시 볼 것"
같은 짧은 기록을 미디어와 함께 보고 싶다. 파일 이름을 매번 바꾸면 원본 이름을 잃고,
별도 메모 앱을 쓰면 어떤 파일에 대한 기록인지 다시 찾아야 한다.

이 기능은 메모를 미디어 파일 자체의 EXIF나 컨테이너에 쓰지 않는다. 대신 **미디어가 있는
각 폴더에 메모 파일 하나**를 두고 그 폴더의 사진·동영상 메모를 함께 저장한다.

## 2. 목표 / 비목표

**목표**

1. 사진과 동영상에 여러 줄의 일반 텍스트 메모를 작성·수정·삭제할 수 있다.
2. MEDIA 폴더 화면에서 어떤 항목에 메모가 있는지 즉시 알 수 있고, 그 자리에서 편집할 수 있다.
3. 전체 화면 미디어 뷰어에서는 메모가 있는 경우 하단 조작부 바로 위의 반투명 바에 메모를
   한 줄로 표시한다.
4. 긴 메모는 표시 영역에서 말줄임표(`…`)로 줄이고, 원문은 편집 화면에서 모두 보여준다.
5. 메모는 폴더마다 sidecar 파일 하나에 저장한다.
6. 미디어를 다른 폴더로 이동해도 메모를 찾아서 옮기거나 새 폴더에 복제하지 않는다.

**비목표**

- 미디어 파일의 EXIF, XMP, MP4/MOV 컨테이너 자체에 메모를 삽입하는 것.
- 파일 이동·복사·이름 변경 때 메모를 자동으로 따라가게 하는 것.
- 여러 메모, 댓글, 태그, 별점, 체크리스트, 그림 메모, 음성 메모.
- 메모 전문 검색, 메모만 모아보기, 정렬·필터 기준으로 메모 사용.
- 클라우드 동기화, 충돌 병합, 계정별 메모, 암호화.
- LIST·GRID 보기나 일반 파일 상세 화면에 메모를 표시하는 것.
- 폴더 자체나 이미지·동영상이 아닌 파일에 메모를 다는 것.

## 3. 사용자 흐름

### 3.1 새 메모 만들기

MEDIA 폴더 화면에서 사진 또는 동영상의 `⋮`를 누르고 **메모**를 선택한다. 전체 화면
미디어 뷰어에서도 `⋮ → 메모`로 같은 편집기를 열 수 있다.

메모가 아직 없을 때는 타일 배지나 뷰어 메모 바를 빈 상태로 표시하지 않는다. 따라서 `⋮ → 메모`가
새 메모를 만드는 명시적인 진입점이다.

### 3.2 기존 메모 보기·편집하기

- MEDIA 폴더 화면: 메모 배지를 탭한다.
- 전체 화면 미디어 뷰어: 메모 바를 탭한다.
- 두 화면 모두: `⋮ → 메모`를 선택해도 같은 편집기가 열린다.

저장에 성공하면 편집기를 닫고 현재 타일과 현재 뷰어 페이지를 즉시 갱신한다. 취소하거나 시스템
뒤로가기를 누르면 변경 전 내용으로 돌아간다.

### 3.3 메모 삭제하기

편집 화면에서 내용을 모두 지우고 **저장**하면 메모를 삭제한다. 별도의 휴지통 버튼은 두지 않는다.
삭제 뒤 MEDIA 타일의 배지와 뷰어의 메모 바가 즉시 사라진다.

앞뒤 공백과 줄바꿈만 있는 내용도 빈 메모로 간주한다. 다만 내용이 있는 메모의 앞뒤 공백은
저장할 때 임의로 다듬지 않는다.

## 4. 화면 구성

### 4.1 MEDIA 폴더 화면

메모가 있는 미디어 타일의 **우하단**에 작은 메모 아이콘을 둔다. 기존 `⋮`는 우상단,
동영상 `▶` 표시는 좌하단이므로 서로 겹치지 않는다.

```text
메모 없는 사진              메모 있는 사진              메모 있는 동영상
┌─────────────┐            ┌─────────────┐            ┌─────────────┐
│           ⋮ │            │           ⋮ │            │           ⋮ │
│             │            │             │            │             │
│   썸네일     │            │   썸네일     │            │   썸네일     │
│             │            │             │            │             │
│             │            │          📝 │            │ ▶        📝 │
└─────────────┘            └─────────────┘            └─────────────┘
```

| 항목 | 규칙 |
|---|---|
| 보이는 아이콘 | 20~24dp의 흰색 메모 glyph |
| 아이콘 배경 | 검정 50% 원형 스크림 |
| 터치 영역 | 최소 48dp, 타일 우하단 모서리에 고정 |
| 탭 | 해당 항목의 메모 편집기 열기 |
| 타일 본문 탭 | 기존대로 미디어 열기 |
| 롱프레스 | 기존대로 선택 모드 진입 |
| 선택 모드 | 메모 배지를 숨기고 기존 선택 오버레이·체크 표시를 우선 |
| 폴더·날짜 타일 | 메모 배지를 표시하지 않으며 메모 메뉴도 없음 |

배지는 **메모가 있다는 사실만** 나타낸다. 격자 밀도를 유지하기 위해 메모 내용은 타일 위에
직접 표시하지 않는다. 배지의 content description은 `메모 있음, 편집`처럼 상태와 동작을 함께
설명한다.

### 4.2 전체 화면 동영상 뷰어

메모가 있는 경우 `rw / play·pause / ff` 주 조작 행 바로 위에 한 줄짜리 반투명 바를 둔다.
바와 재생 조작부는 같은 하단 인셋 및 표시/숨김 상태를 따른다.

```text
┌────────────────────────────────┐
│ ←                          ⋮   │
│                                │
│                                │
│            동영상               │
│                                │
│ ┌────────────────────────────┐ │
│ │ 백스윙 때 왼쪽 무릎이 먼저… │ │  ← 메모 바
│ └────────────────────────────┘ │
│          ↶      ▶      ↷       │  ← rw / play / ff
│  0:03 ━━━━━●──────────── 0:47  │
└────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 위치 | 주 조작 행 바로 위, 좌우 16dp 여백 |
| 높이 | 한 줄 텍스트와 상하 여백을 포함한 고정 높이. 최소 터치 높이 48dp |
| 배경 | 검정 50%의 라운드 사각형 |
| 글자 | 흰색, 한 줄, 끝 말줄임(`ellipsize=end`) |
| 정렬 | 로케일의 start 정렬. RTL에서는 방향을 반전 |
| 탭 | 현재 미디어의 메모 편집기 열기 |
| 메모 없음 | 바 전체를 `GONE` 처리해 빈 공간을 남기지 않음 |
| 컨트롤 숨김 | 앱 바·재생 컨트롤과 함께 숨김 |

메모가 길어도 바를 두 줄 이상 키우지 않는다. 재생 화면을 가리는 면적과 주 조작부 위치가
메모 길이에 따라 달라지지 않아야 한다.

### 4.3 전체 화면 사진 뷰어

사진에는 `rw / play / ff` 조작 행이 없으므로, 동영상 메모 바와 같은 좌우 여백·높이로
**하단 시스템 인셋 위 16dp**에 둔다. 동영상과 마찬가지로 뷰어 크롬이 보일 때만 나타난다.

```text
┌────────────────────────────────┐
│ ←                          ⋮   │
│                                │
│                                │
│             사진                │
│                                │
│                                │
│ ┌────────────────────────────┐ │
│ │ 임팩트 순간 오른발 뒤꿈치…  │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

사진을 확대·이동하는 제스처보다 메모 바의 탭을 우선한다. 바 바깥의 사진 제스처, 한 번 탭해
크롬을 숨기는 동작, 아래로 스와이프해 닫기는 기존대로 유지한다.

### 4.4 메모 편집기

휴대폰에서는 모달 대화상자, 충분히 넓은 화면에서는 같은 내용의 폭 제한 대화상자로 표시한다.

```text
┌──────────────────────────────┐
│ 메모                         │
│ IMG_20260915_143210.MP4      │
│ ┌──────────────────────────┐ │
│ │ 백스윙 때 왼쪽 무릎이     │ │
│ │ 먼저 움직임.              │ │
│ │                          │ │
│ └──────────────────────────┘ │
│                    취소  저장 │
└──────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 제목 | `메모` |
| 보조 정보 | 현재 파일 이름, 한 줄 끝 말줄임 |
| 입력 | 여러 줄 일반 텍스트, 첫 진입 시 자동 포커스와 키보드 표시 |
| 최대 길이 | 2,000자. 줄바꿈도 한 글자로 계산 |
| 버튼 | `취소`, `저장` |
| 저장 중 | 중복 탭을 막고 진행 상태 표시 |
| 회전·폴더블 전환 | 입력 중인 미저장 내용을 보존 |

최대 길이에 도달하면 더 입력되지 않게 하고 현재 글자 수를 안내한다. 텍스트는 서식 없는
Unicode 문자열로 저장하며 URL 자동 링크, Markdown 렌더링, HTML 해석은 하지 않는다.

## 5. 노출 범위

| 화면 | 메모 배지·내용 | 메모 메뉴 |
|---|---|---|
| 파일 목록 LIST | 표시하지 않음 | 없음 |
| 파일 목록 GRID | 표시하지 않음 | 없음 |
| 파일 목록 MEDIA | 메모가 있으면 타일 배지 | 사진·동영상에 있음 |
| 전체 화면 미디어 뷰어 | 메모가 있으면 메모 바 | 항상 있음 |
| 일반 파일 상세/검색 결과 | 표시하지 않음 | 없음 |

전체 화면 미디어 뷰어는 MEDIA 타일, LIST·GRID, 외부 열기 중 어느 경로로 진입했는지와 관계없이
현재 파일의 부모 폴더를 읽을 수 있으면 메모를 표시한다. 여기서 "미디어 뷰에서만 노출"은
**파일 목록에서는 MEDIA 보기만**, 파일을 연 뒤에는 **PhotoExplorer의 미디어 뷰어만**을 뜻한다.

## 6. 폴더별 메모 파일

### 6.1 위치와 이름

메모가 처음 저장될 때 미디어와 같은 폴더에 다음 파일을 하나 만든다.

```text
.photoexplorer-media-notes.json
```

- 한 폴더의 모든 사진·동영상 메모를 이 파일 하나에 저장한다.
- 메모가 하나도 남지 않으면 파일을 삭제한다.
- PhotoExplorer의 LIST·GRID·MEDIA, 검색 결과와 폴더 항목 수에서는 이 예약 파일을 항상 제외한다.
- 다른 파일 관리자나 PC에서는 보일 수 있다. 이름 앞의 `.`은 보조적인 숨김일 뿐 보안 기능이 아니다.
- 같은 이름의 사용자 파일이 이미 있는데 유효한 PhotoExplorer 메모 파일이 아니면 덮어쓰지 않고,
  편집 시 충돌 오류를 알린다.

### 6.2 형식

UTF-8 JSON을 사용하고, 파일 이름을 폴더 안의 식별자로 삼는다.

```json
{
  "version": 1,
  "notes": {
    "IMG_20260915_143210.MP4": {
      "text": "백스윙 때 왼쪽 무릎이 먼저 움직임.",
      "updatedAt": "2026-09-15T14:40:12+09:00"
    },
    "IMG_20260915_143245.JPG": {
      "text": "임팩트 순간 확인.",
      "updatedAt": "2026-09-15T14:42:03+09:00"
    }
  }
}
```

| 필드 | 의미 |
|---|---|
| `version` | 형식 버전. 알 수 없는 상위 버전은 쓰지 않고 읽기 오류로 처리 |
| `notes` key | 대소문자와 확장자를 포함한 현재 파일 이름 |
| `text` | 최대 2,000자의 원문 |
| `updatedAt` | ISO 8601 갱신 시각. 표시용이 아니라 진단·향후 마이그레이션용 |

JSON 객체 순서에는 의미가 없다. 알 수 없는 필드는 보존하는 것을 원칙으로 하여 이후 형식 확장과
구버전 앱의 왕복 저장에서 데이터 손실을 줄인다.

### 6.3 이동·복사·이름 변경

메모의 소속은 **미디어 내용이 아니라 `부모 폴더 + 파일 이름`**이다.

| 파일 작업 | 메모 처리 |
|---|---|
| 다른 폴더로 이동 | 새 폴더로 메모를 옮기지 않음 |
| 다른 폴더로 복사 | 복사본에 메모를 만들지 않음 |
| 같은 폴더에서 이름 변경 | 새 이름으로 메모를 옮기지 않음 |
| 파일 삭제 | 메모 레코드를 자동 복원·전달하지 않음 |

원본 폴더 메모 파일의 연결되지 않은 레코드는 즉시 지우지 않는다. 앱 밖에서 파일을 잠시 옮겼다가
같은 이름으로 되돌린 경우 메모가 다시 보이는 단순하고 예측 가능한 규칙을 택한다. 다만 사용자가
해당 폴더에서 다른 메모를 저장할 때, 존재하지 않는 파일의 레코드는 정리할 수 있다. 구현 계획에서
provider별 열거 비용을 확인한 뒤 정리 시점을 확정한다.

이 기능은 파일의 고유 ID나 내용 해시로 미디어를 추적하지 않는다. 따라서 요구사항대로 메모가
다른 폴더의 파일을 따라가지 않는다.

### 6.4 안전한 저장

1. 기존 파일 전체를 읽어 알 수 없는 필드를 포함한 최신 상태를 기준으로 수정한다.
2. 가능한 provider에서는 같은 폴더의 임시 파일에 쓴 뒤 교체하여 중간까지만 기록된 파일을 남기지 않는다.
3. 원자적 교체를 지원하지 않는 provider에서는 백업 가능한 쓰기 순서를 사용하고 실패를 사용자에게 알린다.
4. 저장 성공을 확인하기 전에는 화면의 메모를 확정 상태로 바꾸지 않는다.
5. 파싱할 수 없는 파일은 빈 파일로 간주해 덮어쓰지 않는다. 읽기 오류와 복구 필요성을 알린다.

동시에 두 창이나 두 기기에서 같은 파일을 편집하는 충돌 병합은 이번 범위가 아니다. 저장 직전에
파일의 변경 시각 또는 내용 토큰이 달라졌다면 조용히 덮어쓰지 않고 다시 열도록 안내한다.

## 7. 로딩과 상태 갱신

- MEDIA 폴더에 들어오면 sidecar 파일은 폴더당 한 번만 비동기로 읽는다.
- 메모 파일 읽기가 끝나기 전에도 타일과 썸네일을 먼저 표시한다. 읽기 때문에 최초 목록 표시나
  스크롤을 막지 않는다.
- 읽기가 끝나면 현재 화면에 보이는 타일부터 메모 배지를 갱신한다.
- 뷰어에서 앞뒤 페이지로 이동할 때는 같은 폴더의 메모 map을 재사용한다.
- 저장 성공 뒤 폴더 화면과 뷰어가 같은 폴더를 보고 있으면 둘의 캐시를 즉시 무효화·갱신한다.
- 앱 밖에서 sidecar가 바뀐 경우 폴더 새로고침, 재진입 또는 provider 변경 알림 때 다시 읽는다.
- sidecar 읽기 실패는 미디어 목록이나 재생 실패로 전파하지 않는다. 메모만 숨기고 오류 상태를
  `⋮ → 메모` 진입 시 명확히 알린다.

## 8. 권한·오류 상태

| 상태 | 표시 | 편집 |
|---|---|---|
| 폴더 읽기·쓰기 가능 | 정상 표시 | 가능 |
| sidecar 읽기 가능, 폴더 쓰기 불가 | 기존 메모 표시 | 편집기는 열되 저장 불가 안내 |
| sidecar 없음, 폴더 쓰기 불가 | 아무 배지·바 없음 | `메모를 저장할 수 없는 위치입니다` 안내 |
| sidecar 손상/지원하지 않는 버전 | 메모를 임의로 표시하지 않음 | 덮어쓰지 않고 복구 안내 |
| 저장 중 파일 사라짐/권한 상실 | 이전 표시 유지 | 편집 내용을 보존한 채 재시도 또는 취소 가능 |

로컬 저장소뿐 아니라 SAF, SMB, SFTP, FTP, WebDAV 등 현재 앱이 열 수 있는 provider에서도
동일한 UX를 목표로 한다. 다만 같은 폴더에 파일을 만들 수 없는 읽기 전용 provider는 표시만
지원하거나 메모 기능을 사용할 수 없다. archive 내부에는 sidecar를 만들지 않는다.

## 9. 접근성·입력

1. 메모 배지와 메모 바는 최소 48dp 터치 영역을 갖는다.
2. TalkBack은 타일에서 `파일 이름 → 동영상 여부 → 메모 있음, 편집 → 메뉴` 순서로 접근할 수 있다.
3. 뷰어 메모 바는 화면에 보이는 축약문이 아니라 가능한 경우 **전체 메모**를 접근성 설명으로 읽는다.
4. 글꼴 크기를 키워도 메모 바는 한 줄 말줄임을 유지하고 주 조작부와 겹치지 않는다.
5. 하드웨어 키보드의 `Ctrl+Enter`는 저장, `Esc`는 취소로 동작한다. 일반 Enter는 줄바꿈이다.
6. 색만으로 메모 존재 여부를 전달하지 않고 메모 glyph와 content description을 함께 제공한다.
7. RTL에서는 텍스트와 논리적 start/end만 반전하고 메모 glyph 자체는 반전하지 않는다.

## 10. 예상 변경 영역

이 절은 구현 순서를 확정하는 계획서가 아니라 현재 구조에서의 영향 범위를 기록한다.

| 파일/영역 | 예상 변경 |
|---|---|
| `file_item_media.xml` | 우하단 메모 배지와 48dp 터치 영역 추가 |
| `FileListAdapter.kt` | MEDIA 타일의 메모 상태 bind, 재사용 시 상태 초기화 |
| `FileListFragment.kt`와 항목 메뉴 | MEDIA에서만 `메모` 항목 노출, 편집기 호출과 저장 뒤 갱신 |
| `media_viewer_fragment.xml` | 동영상 컨트롤 위/사진 하단에 공용 메모 바 배치 |
| `MediaViewerFragment.kt` | 현재 페이지별 메모 로딩, 바 표시·말줄임·편집, 크롬 표시 상태 연동 |

구현 시 현재 워킹트리에서 진행 중인 동영상 이동 단위/배속 변경과 겹치는
`MediaViewerFragment.kt`, `media_viewer.xml`, 문자열 리소스는 병합 충돌 없이 보존해야 한다.

## 11. 수용 기준

1. MEDIA 폴더 화면에서 메모가 있는 사진·동영상만 우하단 메모 배지가 보인다.
2. LIST·GRID, 날짜 타일, 폴더 타일, 비미디어 파일에는 메모 UI가 보이지 않는다.
3. 메모 없는 미디어도 `⋮ → 메모`에서 새 메모를 만들 수 있다.
4. 메모 배지를 누르면 해당 파일의 기존 원문이 열린다. 타일의 다른 영역은 기존대로 파일을 연다.
5. 동영상 뷰어에서 메모 바가 `rw / play / ff` 바로 위에 나타난다.
6. 사진 뷰어에서 메모 바가 하단 시스템 인셋 위에 나타난다.
7. 긴 메모는 바 한 줄 끝에서 `…`로 줄어들고, 바 높이와 재생 조작부 위치가 변하지 않는다.
8. 메모 바를 누르면 전체 원문을 가진 편집기가 열린다.
9. 메모가 없으면 뷰어에 빈 바나 빈 공간이 남지 않고 `⋮ → 메모`로 만들 수 있다.
10. 내용을 모두 지워 저장하면 타일 배지와 뷰어 바가 즉시 사라진다.
11. 메모 바는 앱 바·재생 컨트롤과 함께 나타나고 사라지며 몰입형 감상을 방해하지 않는다.
12. 사진 확대·이동, 좌우 페이지 이동, 아래로 스와이프 닫기, 동영상 seek·재생 버튼에 회귀가 없다.
13. 폴더에는 sidecar가 최대 하나만 생기고 여러 미디어 메모가 그 안에 함께 저장된다.
14. 미디어를 다른 폴더로 이동·복사하거나 이름을 바꿔도 메모가 새 경로·이름을 따라가지 않는다.
15. 예약 sidecar 파일은 PhotoExplorer의 파일 목록, 검색 결과, 항목 개수에 나타나지 않는다.
16. sidecar 손상, 알 수 없는 버전, 읽기 전용 폴더에서 기존 파일을 조용히 덮어쓰지 않는다.
17. 수백 개 미디어가 있는 폴더에서도 메모 읽기 때문에 첫 타일 표시와 스크롤이 멈추지 않는다.
18. 화면 회전·접기/펼치기 뒤에도 편집 중인 미저장 내용이 남는다.
19. 밝은·어두운·검정 야간 테마와 큰 글꼴에서 바·배지·편집기가 읽히고 터치 영역이 유지된다.
20. 한국어, 영어, RTL 로케일에서 파일 이름·메모·버튼이 겹치지 않는다.

| D8 | 최대 길이는 2,000자이고 서식 없는 텍스트로 저장한다 | 짧은 관찰 메모에는 충분하면서 파일·접근성 설명의 무제한 증가를 막음 |
| D9 | 손상되거나 더 최신 버전인 sidecar는 자동 덮어쓰지 않는다 | 메모 데이터의 조용한 유실을 방지 |

## 14. 구현 계획 전에 확정할 항목

다음 항목은 요구사항의 방향을 바꾸지는 않지만 provider 구현을 조사한 뒤 수치를 확정해야 한다.

1. 연결되지 않은 메모 레코드를 정리할 정확한 시점과, 원격 provider에서는 정리를 생략할지 여부.
2. provider별 원자적 교체 지원 여부와 원자적 교체가 없을 때의 백업 파일 이름·복구 절차.
3. 사진 뷰어의 하단 바가 공유 요소 전환 및 swipe-down 좌표계와 겹치지 않는 최종 16dp 위치.
4. 20dp와 24dp 중 MEDIA 타일에서 가장 잘 읽히는 메모 glyph 크기.

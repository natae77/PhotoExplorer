# 11b. 동영상 정밀 이동 기획서

동영상 뷰어의 **10초 뒤로 / 10초 앞으로 버튼**을 정밀 이동 버튼으로 바꾼다.
기본은 영상이 실제로 가진 **프레임 타임스탬프(PTS)의 이전 / 다음 프레임**이고,
필요하면 `⋮` 메뉴에서 **1초 단위 이동**으로 바꾼다.

이 문서는 *무엇을 만들 것인가*만 정의한다. 구현 방법·변경 파일·작업 순서는
별도 구현 계획서에서 다룬다.

- 작성일: 2026-09-13
- 프로젝트: **PhotoExplorer** (`natae77/PhotoExplorer`, `zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 브랜치: `feature/video-precise-seek`
- 상태: **구현 및 Pixel 8 AVD 검증 완료 — 실기기 항목 남음, 미커밋 워킹트리**

**개정 이력** — 11번·11a와 같은 규칙을 쓴다. 개정할 때 새 문서를 만들지 않고
본문을 직접 고친다.

| 개정 | 날짜 | 무엇이 바뀌었나 |
|---|---|---|
| 1차 | 2026-09-13 | 최초 작성 |
| 2차 | 2026-09-13 | §7.2 — 뒤로·재생/일시정지·앞으로 세 버튼의 터치 영역 확대 추가 |
| 3차 | 2026-09-13 | 3-agent 계획 리뷰, 구현 및 결정론적 CFR/VFR+B-frame 에뮬레이터 검증 결과 반영 |
| 4차 | 2026-09-13 | 기존 버튼 모양을 유지하고 프레임·초 모드 모두 가운데 숫자를 `1`로 표시 |

> **11번·11a와의 관계.** 이 문서는 [11번 동영상 뷰어 기획서](11-video-viewer-spec.md)의
> 후속 기획이며, 11번 §2·D10의 **프레임 단위 이동은 비목표**라는 결정을 뒤집는다.
> [11a 뷰어 화면 정리 기획서](11a-viewer-ui-cleanup-spec.md) §2·§4.2의
> **10초 뒤로 / 앞으로 버튼을 유지한다**는 부분도 이 문서로 대체한다.
> 구간 반복(A-B 반복)은 여전히 범위 밖이고, 나머지 11번·11a 결정은 그대로 유효하다.
>
> **결정 번호는 11a를 이어 쓴다.** 11a가 D20에서 끝났으므로 이 문서는 D21부터 시작한다.

## 1. 배경

현재 동영상 컨트롤에는 10초 뒤로, 재생/일시정지, 10초 앞으로 버튼이 있다.
긴 영상을 빠르게 건너뛸 때는 유용하지만, 골프 스윙처럼 짧고 빠른 움직임을 확인할 때는
10초가 너무 크다. 0.25× 배속으로 느리게 볼 수는 있어도 원하는 자세의 바로 전·다음 장면을
한 장씩 비교하기는 어렵다.

단순히 영상의 표시 프레임 레이트로 `1 / fps`초를 계산하는 것도 충분하지 않다.

- 30fps라는 값이 있어도 첫 프레임이 반드시 `0초`에서 시작하지는 않는다.
- 가변 프레임레이트(VFR) 영상은 프레임마다 시간 간격이 다르다.
- 컨테이너가 가진 실제 프레임 타임스탬프가 `0.020, 0.052, 0.091, 0.140…`이라면
  그 값들이 영상의 시간축이다. 평균 간격을 더해서 만든 시각은 실제 프레임과 어긋날 수 있다.

따라서 프레임 이동의 기준은 fps가 아니라 영상에 기록된 **실제 표시 시각(PTS)** 이어야 한다.

## 2. 목표 / 비목표

**목표**

1. 기존 10초 뒤로 / 앞으로 버튼을 **이전 / 다음 정밀 이동 버튼**으로 바꾼다.
2. 정밀 이동의 기본 단위는 **1프레임**이다.
3. 1프레임은 평균 fps로 계산하지 않고, 영상에 기록된 **실제 PTS의 바로 이전 / 다음 값**으로 정의한다.
4. 앱 바 `⋮` 메뉴에서 이동 단위를 **1프레임 / 1초** 중 하나로 고른다.
5. 고정 프레임레이트(CFR)와 가변 프레임레이트(VFR)를 같은 규칙으로 다룬다.
6. 프레임 정보를 준비하거나 읽지 못해도 영상 재생·일시정지·슬라이더는 정상 동작한다.
7. 뒤로·재생/일시정지·앞으로 세 주요 버튼을 빗나가 눌러도 배경 탭으로 처리되지 않도록
   **터치 영역을 넓힌다.**

**비목표 (이번 범위 아님)**

- 구간 반복(A-B 반복)
- 프레임 번호나 PTS를 화면에 숫자로 표시하는 기능
- 특정 프레임을 썸네일 목록으로 펼쳐 고르는 기능
- 프레임을 이미지 파일로 저장하거나 내보내는 기능
- 키프레임만 이동하는 빠른 탐색 모드
- 재생 슬라이더의 동작이나 시간 표시 형식 변경
- 선택한 이동 단위를 앱 재시작 뒤에도 영구 저장하는 기능
- 동영상 편집

## 3. 이동 단위 선택

### 3.1 메뉴 위치

이동 단위는 **동영상 재생 화면의 앱 바 `⋮` 메뉴**에서 고른다.
`재생 속도` 바로 다음, `세부 정보` 바로 앞에 둔다.

```text
재생 속도       ›
이동 단위       ›
  ✓ 1프레임
    1초
세부 정보
삭제
공유
```

- `이동 단위`는 `재생 속도`처럼 하위 메뉴를 가진다.
- `1프레임`과 `1초`는 동시에 고를 수 없는 라디오 선택이다.
- 현재 선택에 체크 표시를 붙인다.
- 메뉴를 고르면 별도 확인 버튼 없이 즉시 반영한다.
- 이 항목은 **동영상 페이지에서만** 보인다. 사진 페이지에서는 보이지 않는다.

### 3.2 기본값과 유지 범위

- 뷰어를 처음 열었을 때 기본값은 **1프레임**이다.
- 같은 뷰어 세션에서 다른 동영상으로 넘겨도 선택은 유지한다.
- 화면 회전 뒤에도 선택을 유지한다.
- 뷰어를 완전히 닫았다가 다시 열면 **1프레임**으로 돌아온다.

재생 속도가 한 뷰어 세션 안에서 공유되고 뷰어를 닫으면 기본값으로 돌아가는
11번 §6.3의 규칙과 같은 수명이다.

## 4. 1프레임 이동

### 4.1 프레임의 정의

이 문서에서 프레임은 영상 트랙에 기록된 **서로 다른 표시 타임스탬프(PTS)** 하나를 뜻한다.
PTS들을 시간순으로 정렬한 목록을 영상의 프레임 시간축으로 본다.

```text
PTS = [0.020, 0.052, 0.091, 0.140, 0.181, ...]
```

평균 프레임 레이트나 `1 / fps` 계산값은 이동 대상을 정하는 데 사용하지 않는다.
세부 정보에 표시되는 fps는 영상 정보일 뿐, 프레임 이동 간격이 아니다.

### 4.2 첫 이동

슬라이더 이동이나 일반 재생 뒤에는 현재 재생 위치가 PTS와 정확히 같지 않을 수 있다.
현재 위치를 `t`라고 할 때 첫 이동 대상은 다음과 같다.

| 버튼 | 선택하는 PTS |
|---|---|
| 이전 프레임 | `t`보다 작은 PTS 중 가장 큰 값 |
| 다음 프레임 | `t`보다 큰 PTS 중 가장 작은 값 |

예를 들어 위 PTS 목록에서 현재 위치가 `0.100초`라면 이전은 `0.091초`, 다음은
`0.140초`다. 현재 위치가 정확히 `0.091초`라면 그 값을 다시 고르지 않고 이전은
`0.052초`, 다음은 `0.140초`다.

### 4.3 연속 이동

한 번 실제 PTS를 골랐으면 그 뒤의 연속 클릭은 재생기의 반올림된 시간값을 다시 해석하지 않고
**PTS 목록의 현재 인덱스에서 정확히 -1 또는 +1** 한다.

이 규칙이 필요한 이유는 PTS가 마이크로초 단위인 반면 화면의 재생 위치는 더 낮은 정밀도로
표현될 수 있기 때문이다. 매번 표시 시간을 기준으로 다시 찾으면 같은 프레임을 반복하거나
하나를 건너뛸 수 있다.

다음 상황에서는 이전에 기억한 PTS 인덱스를 버리고, §4.2의 규칙으로 현재 위치에서 다시 찾는다.

- 재생을 다시 시작해 시간축이 흘렀을 때
- 슬라이더로 위치를 옮겼을 때
- 1초 이동을 했을 때
- 다른 동영상 페이지로 넘어갔을 때
- 재생 위치가 외부 요인으로 바뀌었을 때

### 4.4 재생 상태

- **프레임 이동 버튼을 누르면 영상을 일시정지하고** 대상 프레임을 보여준다.
- 이미 일시정지 상태라면 그대로 유지한다.
- 이동 단위를 메뉴에서 바꾸는 것만으로는 재생 상태를 바꾸지 않는다.
- 프레임 이동 뒤 재생 버튼을 누르면 선택한 프레임 위치부터 다시 재생한다.

재생 중인 화면에서 한 프레임만 옮기고 계속 재생하면 사용자가 결과를 확인하기 전에 다음 프레임으로
넘어가므로, 프레임 이동은 일시정지를 동반한다.

### 4.5 처음과 끝

- 첫 PTS에서 이전 프레임을 누르면 첫 프레임에 그대로 머문다.
- 마지막 PTS에서 다음 프레임을 누르면 마지막 프레임에 그대로 머문다.
- 영상의 끝을 넘어 다음 미디어 페이지로 이동하지 않는다.

## 5. 가변 프레임레이트 대응

가변 프레임레이트를 별도 모드로 취급하지 않는다. 실제 PTS 목록의 이웃으로 이동한다는
§4의 규칙 자체가 VFR 대응이다.

```text
PTS 간격 = 32ms, 39ms, 49ms, 41ms, ...
```

이런 영상에서도 다음 버튼은 단순히 목록의 다음 PTS를 고른다. 직전 간격, 평균 간격,
컨테이너의 대표 fps를 다음 간격으로 추정하지 않는다.

사용자가 보는 결과는 다음과 같아야 한다.

- 짧게 노출된 프레임도 건너뛰지 않는다.
- 오래 유지되는 프레임을 가상의 여러 프레임으로 나누지 않는다.
- 첫 프레임의 PTS가 0이 아니어도 실제 첫 PTS부터 시작한다.
- 프레임 사이의 간격이 달라도 버튼을 한 번 누를 때 실제 프레임 하나만 이동한다.

## 6. 1초 이동

1초 모드는 현재 재생 위치를 기준으로 정확히 1초 전·후를 요청한다.

| 버튼 | 동작 |
|---|---|
| 뒤로 | 현재 위치 - 1초 |
| 앞으로 | 현재 위치 + 1초 |

- 영상 시작보다 앞이면 0초에 머문다.
- 영상 끝보다 뒤면 마지막 위치에 머문다.
- 재생 중이었다면 이동 뒤에도 재생하고, 일시정지 중이었다면 그대로 멈춰 있는다.
- 1초 지점에 정확히 일치하는 PTS가 없으면 재생기가 그 시각에 표시해야 할 프레임을 보여준다.

1초 모드는 “30프레임 이동”이 아니다. 영상의 fps나 VFR 여부와 관계없이 시간축에서 1초를 이동한다.

## 7. 버튼 표시·터치 영역·접근성

### 7.1 표시와 접근성

버튼의 위치와 원형 스크림은 11a §4의 현재 레이아웃을 유지한다. 가운데 재생/일시정지 버튼도
그대로 둔다.

| 선택 단위 | 뒤로 / 앞으로 버튼 안 표시 | 접근성 설명 |
|---|---|---|
| 1프레임 | `1` | “1프레임 뒤로 이동” / “1프레임 앞으로 이동” |
| 1초 | `1` | “1초 뒤로 이동” / “1초 앞으로 이동” |

- 단위를 바꾸면 두 버튼의 표시와 접근성 설명을 즉시 갱신한다.
- 버튼의 원형 배경, 화살표와 숫자 배치는 기존 10초 버튼 모양을 그대로 유지한다.
- 가운데 숫자만 기존 `10`에서 `1`로 바꾸며, 프레임과 초의 구분은 메뉴 선택과
  접근성 설명으로 제공한다.
- 한국어와 영어 문자열을 모두 제공한다.

### 7.2 세 주요 버튼의 터치 영역

대상은 하단 중앙의 다음 세 버튼이다.

1. 뒤로
2. 재생 / 일시정지
3. 앞으로

현재 세 버튼은 52dp 원형 스크림 안에 32dp 조작 뷰가 들어 있다. 사용자가 원의 가장자리나
버튼 사이 가까운 곳을 누르면 버튼이 아니라 영상 바탕을 누른 것으로 처리될 수 있다.
이때 앱 바와 컨트롤이 사라져 다시 화면을 탭해야 한다.

세 버튼은 각각 **가로 68dp × 세로 최소 64dp의 독립된 터치 셀**을 갖는다.

- 52dp 원형 스크림과 아이콘 크기는 그대로 둔다. 보이는 버튼을 키우지 않는다.
- 원형 스크림 바깥의 투명 여백도 해당 버튼의 터치 영역에 포함한다.
- `(뒤로) | (재생/일시정지) | (앞으로)` 세 셀은 서로 겹치지 않는다.
- 버튼 사이에서는 두 버튼 중심의 정확한 중간 지점을 경계로 삼는다. 경계의 한쪽 탭이
  옆 버튼으로 넘어가거나 두 버튼이 함께 반응하는 경우가 없어야 한다.
- 현재 버튼 중심 간격이 68dp이므로 각 셀의 가로 폭도 68dp로 잡으면, 세 셀 사이에
  배경 탭으로 빠지는 빈틈 없이 현재 컨트롤 폭을 나눌 수 있다.
- 넓어진 영역 어디를 눌러도 그 버튼을 정확히 누른 것으로 처리한다.
- 세 버튼 영역에서 발생한 탭은 영상 바탕으로 전달하지 않는다. 따라서 버튼을 빗나갔다는 이유로
  앱 바와 재생 컨트롤이 사라지지 않는다.
- 프레임 정보를 준비 중이라 뒤로/앞으로가 잠시 비활성화된 경우에도 그 버튼 영역의 탭을
  배경 탭으로 처리하지 않는다. 아무 동작 없이 컨트롤을 그대로 유지한다.
- 세 버튼 영역 바깥의 영상 바탕을 누르는 기존 표시/숨김 동작은 그대로 유지한다.

세로 64dp는 Android의 최소 터치 타깃보다 여유가 있다. 가로는 현재 배치의 중심 간격에 맞춰
68dp로 나누므로 터치 영역 확대가 가운데 버튼과의 간섭을 만들지 않는다. 실제 확장 방법은
구현 계획에서 정한다.

## 8. 프레임 정보 준비와 실패

프레임 이동에는 영상 전체의 실제 PTS 목록이 필요하지만, 그 준비 때문에 영상 재생 시작이나
페이지 전환을 막아서는 안 된다.

- 프레임 정보를 준비하는 동안에는 프레임 이동 버튼만 비활성화한다.
- 재생/일시정지, 슬라이더, 1초 이동 선택은 계속 사용할 수 있다.
- 준비가 끝나면 현재 화면을 다시 열지 않아도 프레임 버튼이 활성화된다.
- 프레임 정보를 읽을 수 없으면 fps로 간격을 추정해 **프레임 이동인 것처럼 동작하지 않는다.**
- 읽지 못한 경우 프레임 버튼은 비활성 상태로 두고, 사용자는 `⋮` → 이동 단위 → `1초`를
  선택할 수 있다.
- 읽기 실패나 안전한 메모리 상한 초과로 프레임 이동을 쓸 수 없으면, 접근성 설명과 짧은 안내로
  **“프레임 정보를 읽을 수 없음 — 이동 단위에서 1초를 선택할 수 있음”** 을 알린다.
- 프레임 정보 준비 실패가 영상 재생 실패로 이어져서는 안 된다.

별도의 전체 화면 로딩 표시나 가운데 스피너는 추가하지 않는다. 준비 시간과 메모리 사용을
어떻게 제한할지는 구현 계획에서 정한다.

## 9. 정확도의 경계

정밀 이동의 목표는 **키프레임 이동이 아니라 실제 표시 프레임 이동**이다. 압축 영상은 목표
프레임을 보여주기 위해 앞쪽 키프레임부터 디코딩해야 할 수 있으므로, 한 프레임 이동도 영상과
기기에 따라 잠깐 늦을 수 있다. 속도를 위해 가까운 키프레임에서 멈추는 것으로 바꾸지 않는다.

일반적인 MP4/MOV의 H.264·HEVC 영상과 앱의 실제 테스트 데이터에서 실제 PTS 순서대로 한 장씩
보이는 것을 수용 기준으로 삼는다. 특수한 컨테이너·코덱에서 하나의 저장 샘플과 하나의 표시
프레임이 대응하지 않는 경우까지 자체 디코더를 만들어 보정하는 것은 이번 범위가 아니다.

## 10. 기존 동작 중 그대로 두는 것

- 재생/일시정지 버튼
- 재생 슬라이더와 현재 시간/전체 길이 표시
- `⋮` → 재생 속도와 여섯 개 배속
- `⋮` → 세부 정보, 삭제, 공유
- 탭으로 앱 바와 컨트롤을 같이 표시/숨김
- 사진과 동영상 사이 좌우 넘김
- 아래로 스와이프해 닫기
- 뷰어 세션 안에서 동영상별 재생 위치 기억
- 백그라운드·오디오 포커스·화면 꺼짐 처리

| 13 | 세 주요 버튼의 원 가장자리와 바깥 투명 여백을 눌러도 해당 버튼이 동작하는가 | 실제 사용에서 빗나가는 문제 재현 |

| 15 | 비활성화된 프레임 버튼 주변을 눌러도 컨트롤이 사라지지 않는가 | 탭이 영상 바탕으로 새지 않는지 확인 |

## 12. 수용 기준

1. 동영상 뷰어의 기존 10초 뒤로 / 앞으로 버튼이 정밀 이동 버튼으로 바뀐다.
2. 뷰어를 새로 열면 두 버튼의 기본 단위가 **1프레임**이고 기존 버튼 모양 안에 `1`이 보인다.
3. `⋮` 메뉴에서 **재생 속도 바로 다음**에 `이동 단위`가 보인다.
4. `이동 단위` 하위 메뉴에서 `1프레임`과 `1초` 중 하나를 고를 수 있고 현재 값에 체크가 붙는다.
5. 사진 페이지에서는 `이동 단위` 메뉴가 보이지 않는다.
6. 프레임 앞으로를 한 번 누르면 현재 위치보다 큰 실제 PTS 중 가장 가까운 프레임으로 간다.
7. 프레임 뒤로를 한 번 누르면 현재 위치보다 작은 실제 PTS 중 가장 가까운 프레임으로 간다.
8. 현재 위치가 정확히 PTS와 같으면 그 프레임을 반복하지 않고 바로 이웃한 PTS로 간다.
9. 프레임 버튼을 연속해서 누를 때 실제 PTS 목록에서 정확히 한 항목씩 이동한다.
10. 가변 프레임레이트 영상에서도 평균 간격을 추정하지 않고 실제 PTS 순서로 이동한다.
11. 프레임 버튼을 누르면 재생이 멈추고 대상 프레임이 화면에 남는다.
12. 1초 모드에서는 정확히 ±1초를 요청하고 기존 재생/일시정지 상태를 유지한다.
13. 이동 단위 선택은 다른 동영상과 화면 회전 뒤에도 유지되고, 뷰어를 닫으면 1프레임으로 돌아간다.
14. 프레임 정보 준비 중에도 영상 재생, 슬라이더, 페이지 전환이 막히지 않는다.
15. 프레임 정보를 읽지 못할 때 fps 추정 이동으로 조용히 대체하지 않는다.
16. 재생 속도·세부 정보·삭제·공유·사진 보기·좌우 넘김·아래로 닫기가 이전과 같이 동작한다.
17. 뒤로·재생/일시정지·앞으로 버튼이 각각 68dp × 최소 64dp의 독립된 터치 셀을 가진다.
18. 세 버튼의 원 가장자리와 바깥 투명 여백을 눌러도 해당 버튼이 동작한다.
19. 세 버튼의 확장 영역을 눌렀을 때 탭이 영상 바탕으로 처리되어 컨트롤이 사라지지 않는다.
20. (1) 뒤로나 (3) 앞으로 영역을 눌렀을 때 (2) 재생/일시정지가 반응하지 않으며,
    어떤 경계에서도 두 버튼이 함께 반응하지 않는다.

# 11. 동영상 뷰어 기획서

폰으로 찍은 동영상(아이폰 `.mov`, 갤럭시 `.mp4`)을 **앱 안에서 바로 재생**한다.
지금은 동영상을 누르면 외부 앱으로 넘어간다.

이 문서는 *무엇을 만들 것인가*만 정의한다. 구현 방법·작업 순서는 별도 계획서에서 다룬다.

- 작성일: 2026-08-28
- 프로젝트: **PhotoExplorer** (`natae77/PhotoExplorer`, `zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 브랜치: `feature/video-viewer` (`feature/media-view-mode` 끝에서 분기)
- 상태: **확정** — 남은 것은 실측 확인뿐(§11)

**개정 이력** — 이 문서는 개정할 때 새 문서를 만들지 않고 **본문을 직접 고친다.**
무엇이 바뀌었는지는 여기에, 정확한 변경 내용은 git 이력에 남는다.

| 개정 | 날짜 | 무엇이 바뀌었나 |
|---|---|---|
| 1차 | 2026-08-28 | 최초 작성 |
| 2차 | 2026-08-28 | 구현 결과 반영 — §5.3 오디오 포커스 복귀 시 자동 재개로 수정, §11 실측 결과 기입 |
| 3차 | 2026-08-29 | §6.1·§6.3의 컨트롤 외형·배속 표시 규칙을 [11a](11a-viewer-ui-cleanup-spec.md)로 넘김 |

> **08번과의 관계**: 08번 기획서 §2는 "사진 뷰어/편집기 개선"을 비목표로 뒀다.
> 이 문서는 그 비목표를 뒤집는 것이 아니라 **별건**으로 다루는 것이며,
> 미디어 보기 모드(08·09)의 어떤 단계에도 의존하지 않는다.
> 다만 **촬영 시각을 읽는 규칙만은 08번 §5를 그대로 물려받는다**(§7.2).
> 목록의 날짜와 뷰어의 촬영 시각이 어긋나면 안 되기 때문이다.
>
> **`feature/swipe-down`과는 겹치지 않는다.** 그 브랜치의 "아래로 스와이프해서 닫기"는
> 이 브랜치에 들어있지 않고, 이 문서도 그것을 전제하지 않는다. 두 작업이 합쳐진 뒤에
> 동영상 페이지에도 같은 제스처를 적용할지는 **그때 따로 정한다** (D12).

## 1. 배경

파일 목록에서 동영상을 누르면 암시적 VIEW 인텐트가 나가서 **다른 앱**이 뜬다
([FileListFragment.kt:1365](../app/src/main/java/me/zhanghai/android/files/filelist/FileListFragment.kt#L1365) `openFileWithIntent()`).
사진은 그렇지 않다 — `ImageViewerActivity`가 앱 안에서 처리한다.

그래서 사진 20장과 동영상 3개가 섞인 폴더를 훑을 때 흐름이 이렇게 끊긴다.

1. 사진을 눌러 뷰어에 들어간다
2. 좌우로 넘긴다 — **동영상은 목록에 없어서 그냥 건너뛴다**
3. 동영상을 보려면 뷰어를 닫고, 목록에서 그 동영상을 찾아 누른다
4. 다른 앱이 뜬다. 다 보고 나면 그 앱을 닫고 목록으로 돌아온다
5. 다시 사진을 눌러 뷰어에 들어간다

08번에서 만든 미디어 보기 모드는 사진과 동영상을 **한 격자에** 촬영 순서대로 늘어놓는다.
격자에서는 한 덩어리인데 뷰어에서는 갈라지는 셈이다.

재생 라이브러리는 아직 없다. `coil-video`([app/build.gradle:197](../app/build.gradle#L197))가 있지만
이건 썸네일용 프레임 추출이지 재생기가 아니다.

## 2. 목표 / 비목표

**목표**

1. 로컬·SAF 경로의 동영상을 **뷰어 안에서 재생**한다. 사진과 **같은 뷰어**에서, 좌우로 이어서 넘긴다.
2. **재생 슬라이더**로 원하는 지점에 간다.
3. **재생 속도**를 0.25×~2× 사이에서 고른다.
4. 지금 보는 동영상의 **세부 정보**(해상도·코덱·프레임 레이트·촬영 시각 등)를 재생을 멈추지 않고 본다.
5. 기존 사진 뷰어 동작(좌우 넘김, 탭으로 앱 바 토글, 확대, 삭제·공유)을 깨뜨리지 않는다.

**비목표 (이번 범위 아님)**

- **원격(SFTP/SMB/FTP)·아카이브 안의 동영상 재생.** 지금처럼 외부 앱으로 넘긴다 (D3)
- **자막**(폰 촬영 영상에는 없다)
- **음소거 토글, 반복 재생, 다음 동영상 자동 재생** (D9)
- **프레임 단위 이동, 구간 반복(A-B 반복)** — 후속 후보. D10 참고
- **동영상 편집**(자르기·회전 저장 등)
- **PIP(화면 속 화면), 백그라운드 재생**
- **다른 앱에서 동영상을 열 때 PhotoExplorer가 후보로 뜨는 것** — 매니페스트에 `video/*` 필터를 넣지 않는다 (D4)
- **동영상 페이지에서 아래로 스와이프해 닫기** — `feature/swipe-down`의 작업이고 이 브랜치에 없다 (D12)
- 이미지 뷰어의 확대·축소 동작 개선

## 3. 대상 — 무엇을 앱 안에서 재생하는가

**재생 가능(playable)** 의 정의는 다음 둘을 **모두** 만족하는 것이다.

| # | 조건 | 판정 |
|---|---|---|
| 1 | MIME 타입이 동영상 | `mimeType.isVideo` ([MimeTypeTypeExtensions.kt:49](../app/src/main/java/me/zhanghai/android/files/file/MimeTypeTypeExtensions.kt#L49)) |
| 2 | 로컬 파일 또는 SAF 문서 경로 | `path.isLinuxPath` 또는 `path.isDocumentPath` |

`.mov`는 `video/quicktime`, `.mp4`는 `video/mp4`로 이미 매핑돼 있다
([MimeTypeMapCompat.kt:771](../app/src/main/java/me/zhanghai/android/files/compat/MimeTypeMapCompat.kt#L771), [779](../app/src/main/java/me/zhanghai/android/files/compat/MimeTypeMapCompat.kt#L779)).
`.mkv`, `.webm`, `.3gp` 등 다른 동영상도 조건에 맞으면 똑같이 재생 대상이다 —
"폰으로 찍은 것"이 계기일 뿐, MIME 타입으로 판정하지 확장자를 골라내지 않는다.

**조건 2를 만족하지 못하는 동영상**(원격·아카이브)은 지금과 **완전히 똑같이** 동작한다.
뷰어의 페이지 목록에 들어가지 않고, 목록에서 누르면 외부 앱으로 나간다. 사진을 넘기다
만나면 건너뛴다 — 지금 동영상이 그렇듯이.

> **왜 로컬·SAF만인가** (D3): 이 앱의 `Path`는 아카이브·SFTP·SMB·FTP까지 감싸는 추상화다.
> 그것들까지 재생하려면 ExoPlayer에 커스텀 `DataSource`를 붙이고 버퍼링·재시도·취소를
> 직접 다뤄야 한다. "폰으로 찍은 동영상을 본다"는 목적에는 로컬·SAF면 충분하고,
> 나중에 필요해지면 `DataSource` 하나를 더 만드는 것으로 확장할 수 있다.

## 4. 뷰어 구조 — 사진과 한 화면에

### 4.1 이름 정리

`ImageViewerActivity`/`Fragment`/`Adapter`가 사진과 동영상을 함께 다루게 되므로,
08번에서 "Photo 모드 → 미디어 모드"로 정리한 것과 **같은 이유로** 내부 이름을
`MediaViewerActivity`/`Fragment`/`Adapter`로 바꾼다. 사용자에게 보이는 화면 제목
(`image_viewer_title`)도 "미디어 뷰어"에 해당하는 문자열로 바꾼다.

매니페스트의 `image/*` 인텐트 필터는 **그대로 둔다.** 외부 앱에서 사진을 열 때 후보로
뜨는 기존 동작을 유지하되, 동영상용 필터는 추가하지 않는다 (D4).

### 4.2 뷰어 목록에 무엇이 들어가는가

지금 [FileListFragment.kt:1393](../app/src/main/java/me/zhanghai/android/files/filelist/FileListFragment.kt#L1393)
`maybeAddImageViewerActivityExtras()`는 어댑터를 훑으면서 `isImage`인 파일만 담는다.
여기에 **§3의 재생 가능한 동영상**을 더한다.

| 눌린 파일 | 동작 |
|---|---|
| 사진 | 뷰어. 목록 = 그 폴더의 사진 + 재생 가능한 동영상 (기존 정렬 순서 그대로) |
| 재생 가능한 동영상 | 뷰어. 목록은 위와 같고, 그 동영상 위치에서 시작 |
| 재생 불가 동영상 (원격·아카이브) | 지금 그대로 외부 앱 |

날짜 타일을 건너뛰는 기존 방어(`as? FileListItem.File ?: continue`)는 그대로 둔다 —
09번 계획서 §4.1에서 한 번 놓쳐 크래시가 났던 자리다.

목록 길이 상한(`IMAGE_VIEWER_ACTIVITY_PATH_LIST_SIZE_MAX`, `TransactionTooLargeException` 회피)도
그대로 적용된다. 동영상이 섞여 항목 수가 늘어나도 상한을 넘으면 현재 위치 주변만 잘라 보낸다.

### 4.3 페이지 레이아웃

한 페이지 레이아웃(`image_viewer_item.xml`)에는
지금 `PhotoView`와 `SubsamplingScaleImageView`가 겹쳐 있고 이미지 크기에 따라 하나만 보인다.
**동영상 페이지는 별도 레이아웃**으로 분리한다 — 재생용 뷰는 이미지 로딩 경로를 전혀 타지 않고,
같은 레이아웃에 세 번째 뷰를 겹쳐 두면 어느 것이 보이는지 따지는 분기가 늘기만 한다.

어댑터가 항목의 MIME 타입을 보고 사진 페이지와 동영상 페이지 중 하나를 고른다.

## 5. 재생

### 5.1 언제 시작하나

**페이지가 완전히 멈춘 뒤에 자동으로 시작한다.** (D5)

"완전히 멈춘 뒤"가 조건인 이유는, 드래그 도중에 시작하면 여러 장을 빠르게 훑을 때
스쳐 지나가는 동영상마다 소리가 튀기 때문이다. 손가락을 떼고 페이지가 자리를 잡은
다음에 시작한다.

### 5.2 플레이어는 하나다

**재생기 인스턴스는 뷰어 전체에서 하나만 둔다.** 페이지마다 만들지 않는다.

`ViewPager2`의 `offscreenPageLimit = 1`(`ImageViewerFragment.kt:112`)이라
앞뒤 페이지까지 최대 세 개가 살아있다. 하드웨어 디코더는 기기마다 몇 개뿐이라
인스턴스를 페이지 수만큼 만들면 금방 바닥나고, 그때부터 재생이 조용히 실패한다.

하나뿐인 플레이어를 **현재 페이지의 재생 뷰에 붙였다 뗀다.** 페이지를 떠나면
그 페이지의 화면은 마지막 프레임이나 빈 화면이 아니라 **첫 프레임 썸네일**로 돌아간다 —
목록의 썸네일과 같은 그림이라 이어서 보인다.

### 5.3 화면을 벗어날 때 / 돌아올 때

| 상황 | 동작 |
|---|---|
| 홈으로 나가거나 다른 앱으로 전환 | 재생을 멈추고 **플레이어 자원을 놓는다** |
| **뷰어 화면으로 돌아옴** | **멈췄던 위치에서 이어진다.** 자동으로 다시 재생된다 |
| 화면 회전 | 위치를 유지한 채 이어진다 |
| 뷰어가 화면에 있는 채로 오디오 포커스를 뺏김 (알림음 등) | 멈춘다. **포커스를 돌려받으면 다시 재생된다** (2차 개정, 아래 참고) |

자원을 붙잡은 채로 백그라운드에 있으면 다른 앱의 재생을 방해한다. 놓아주되 위치는 기억한다.

전화처럼 **화면을 벗어나게 만드는** 경우는 첫 두 줄이 적용된다 — 통화가 끝나고 뷰어로 돌아오면
멈췄던 위치에서 다시 재생된다.

> **2차 개정(2026-08-28).** 1차에서는 "화면을 벗어나지 않은 채 소리만 뺏긴 경우에는 사용자가
> 직접 재생 버튼을 눌러야 한다"고 정했다. Media3의 오디오 포커스 처리(`handleAudioFocus = true`)는
> 포커스를 돌려받으면 **스스로 재생을 재개한다.** 에뮬레이터에서 전화 수신으로 확인했다 —
> 벨이 울리는 동안 멈추고, 통화가 취소되자 이어서 재생됐다.
> 이것을 막으려면 Media3가 열어 주지 않는 지점을 우회해야 하는데, 자동 재개는 대부분의
> 재생기가 하는 동작이기도 하다. **기획을 Media3 동작에 맞춘다** (12번 계획서 §5.3의 판단).

### 5.4 재생 위치 기억

**같은 뷰어 세션 안에서는 동영상마다 재생 위치를 기억한다.**

동영상을 절반쯤 보다가 옆 사진을 확인하고 돌아오는 일이 잦은 구조다. 돌아왔을 때
처음부터 다시 시작하면 매번 그 지점을 찾아가야 한다.

뷰어를 완전히 닫으면 잊는다. 앱을 다시 켰을 때까지 이어보기는 하지 않는다 —
그러려면 저장소가 필요한데 얻는 것에 비해 무겁다 (D8).

### 5.5 오디오 · 화면

| 항목 | 동작 |
|---|---|
| 소리 | 기기 미디어 볼륨을 따른다. 음소거 토글은 없다 (D9) |
| 오디오 포커스 | **요청한다.** 다른 앱이 소리를 내면 이쪽이 멈춘다 |
| 화면 꺼짐 | **재생 중에는 화면이 꺼지지 않는다.** 멈추면 다시 시스템 설정을 따른다 |
| 회전 | 시스템 설정을 따른다(지금과 같다). 눕히면 가로로 크게 본다 |
| 끝까지 재생됨 | **마지막 프레임에서 멈춘다.** 반복하지 않고, 다음 페이지로 넘어가지도 않는다 (D9) |

## 6. 컨트롤

### 6.1 슬라이더와 버튼

재생 라이브러리가 제공하는 **기본 컨트롤**을 쓴다 (D6). 들어있는 것:

- 재생 / 일시정지
- **재생 슬라이더** — 현재 위치, 버퍼링 구간, 드래그해서 이동
- 현재 시간 / 전체 길이 표기
- 10초 뒤로 / 10초 앞으로

직접 만들지 않는 이유는 부록 D6에 있다. 색상·아이콘은 앱 테마에 맞춘다.

> ⚠️ **컨트롤의 외형은 [11a](11a-viewer-ui-cleanup-spec.md) §4로 대체되었다.**
> 기본 레이아웃 대신 우리 레이아웃을 쓰고(11a D17), 배경 스크림과 톱니바퀴를 뺀다.
> **동작 로직은 여전히 Media3 것이므로 D6의 판단 자체는 유효하다.**
> 위에 적힌 네 가지 구성 요소도 그대로 남는다.

### 6.2 앱 바와 한 몸으로 나타나고 사라진다

화면을 탭하면 **앱 바와 재생 컨트롤이 같이 나타나고 같이 사라진다.**

지금 뷰어는 탭하면 몰입 모드가 토글되면서 앱 바가 오르내린다
(`ImageViewerFragment.kt:92`).
재생 컨트롤이 자기만의 자동 숨김 타이머로 따로 놀면 "앱 바는 사라졌는데 컨트롤은 남아있는"
어정쩡한 상태가 생긴다. 컨트롤의 **자동 숨김은 끄고**, 앱 바를 여닫는 곳에 묶는다.

재생 뷰는 탭하면 자기 컨트롤을 토글하는 기본 동작을 갖고 있는데, 이것이 위의 탭 동작과
충돌한다. **재생 뷰의 자체 탭 처리는 끄고** 기존 탭 리스너 한 곳으로 통일한다.

동영상 페이지를 벗어나면 컨트롤은 사라진다. 사진 페이지에서는 앱 바만 오르내린다.

### 6.3 속도 조절

앱 바 `⋮` 메뉴의 **"재생 속도"** 에서 고른다. 값은 여섯 개다.

`0.25×` · `0.5×` · `0.75×` · `1×` · `1.5×` · `2×`

- 현재 값에 표시가 붙는다(라디오 형태).
- 고르면 **즉시 반영**된다. 재생을 멈추지 않는다.
- ~~**1× 가 아니면 앱 바 부제목에 `1.5×` 처럼 표시**한다.~~
  **폐기 — [11a](11a-viewer-ui-cleanup-spec.md) §3.2, D15.** 앱 바에서 부제목이 통째로 없어지면서
  이 표시도 없어졌다. 현재 배속은 이 메뉴의 라디오 표시로 확인한다.
- 다른 동영상으로 넘어가도 **배속은 유지**된다. 여러 개를 같은 속도로 훑어보는 것이 자연스럽다.
- 뷰어를 닫으면 1×로 돌아간다.

`0.25×`가 들어간 이유는 빠른 동작을 느리게 되돌려 보기 위해서다. 이 프로젝트의 테스트
데이터가 골프 스윙 영상인 것과 같은 맥락이다.

메뉴 항목은 **동영상 페이지일 때만** 보인다. 사진 페이지에서는 나오지 않는다.

## 8. 재생할 수 없을 때

폰 영상은 아이폰 `.mov`가 대개 HEVC(H.265)이고 갤럭시도 HEVC·H.264가 섞인다.
HDR10·HDR10+·Dolby Vision도 흔하다. 기기에 디코더가 없거나 파일이 깨져 있으면 실패한다.

실패하면 그 페이지에 **오류 문구와 "다른 앱으로 열기" 버튼**을 띄운다.
사진 페이지의 오류 표시(`errorText`)와 같은 자리, 같은 모양이다.

"다른 앱으로 열기"는 지금 파일 목록에서 동영상을 눌렀을 때와 **똑같은 인텐트**를 띄운다.
즉 앱 안에서 못 보더라도 막다른 길은 아니고, 이 기능이 생기기 전과 같은 선택지가 남는다.

파일이 없거나 권한이 없을 때도 같은 자리에 오류 문구를 띄운다(이때는 열기 버튼 없음).

## 9. 기존 동작 중 손보는 것

**공유의 MIME 타입.** 지금 뷰어의 공유는 `createSendImageIntent()`를 써서
타입이 `image/*`로 **고정**돼 있다([IntentExtensions.kt:126](../app/src/main/java/me/zhanghai/android/files/util/IntentExtensions.kt#L126),
`ImageViewerFragment.kt:204`).
동영상을 이대로 공유하면 받는 앱이 사진인 줄 알고 잘못 처리한다.
**그 파일의 실제 MIME 타입**을 쓰도록 고친다 — 범용 `createSendStreamIntent(mimeType)`이
바로 아래([:138](../app/src/main/java/me/zhanghai/android/files/util/IntentExtensions.kt#L138))에 이미 있다.

**삭제.** 동영상에서도 그대로 동작해야 한다. 삭제한 페이지를 목록에서 빼고 다음 항목으로
넘어가는 기존 처리를 따르되, **삭제되는 것이 지금 재생 중인 동영상이면 먼저 재생을 멈추고
파일을 놓아준 뒤** 지운다.

## 10. 성능 · 접근성 · 그 밖

- **첫 프레임까지의 시간.** 페이지에 도착한 뒤 화면이 검게 비어 있는 시간이 눈에 띄면 안 된다.
  준비되는 동안에는 목록에서 쓰는 것과 같은 **첫 프레임 썸네일**을 깔아 두고, 재생이 시작되면
  그 위로 덮는다. 화면이 검게 번쩍이지 않는다.
- **훑기.** 여러 페이지를 빠르게 넘길 때 매 페이지마다 디코더를 열었다 닫지 않는다(§5.1).
- **접근성.** 재생/일시정지·슬라이더·속도·세부 정보에 각각 설명을 붙인다.
  세부 정보 시트는 항목마다 "이름: 값" 형태로 읽히게 한다.
- **문자열.** 새로 필요한 것 — 뷰어 제목, "재생 속도", 배속 값 여섯 개, "세부 정보",
  세부 정보 항목 이름들, 재생 오류 문구, "다른 앱으로 열기".
  한국어·영어를 둘 다 넣는다.
- **APK 크기.** 재생 라이브러리가 새로 들어간다. 늘어나는 양은 §11에서 실측한다.

## 12. 수용 기준 (Acceptance Criteria)

1. 파일 목록에서 **동영상을 누르면 앱 안에서 재생**된다. 외부 앱이 뜨지 않는다.
2. 사진과 동영상이 섞인 폴더에서 사진을 눌러 들어간 뒤 **좌우로 넘기면 동영상도 순서대로 나온다.**
3. 동영상 페이지에 손가락을 떼고 **페이지가 자리를 잡으면 자동으로 재생**된다.
4. 빠르게 여러 페이지를 훑을 때 **스쳐 지나가는 동영상의 소리가 나지 않는다.**
5. **슬라이더를 드래그하면 그 지점으로 이동**하고, 현재 시간/전체 길이가 맞게 표시된다.
6. 화면을 탭하면 **앱 바와 재생 컨트롤이 같이** 나타나고, 다시 탭하면 같이 사라진다.
7. `⋮` → 재생 속도에서 **0.25× / 0.5× / 0.75× / 1× / 1.5× / 2×** 를 고를 수 있고, 즉시 반영된다.
8. 1×가 아닌 배속이면 **앱 바 부제목에 배속이 표시**된다. 다음 동영상으로 넘어가도 유지된다.
9. `⋮` → 세부 정보에서 **해상도·길이·프레임 레이트·코덱·촬영 시각**이 나오고, **재생이 계속된다.**
10. 세부 정보의 **촬영 시각이 파일 목록 미디어 모드의 날짜 타일과 같은 날짜**를 가리킨다.
11. 홈으로 나갔다 돌아오면 **멈췄던 위치에서 이어진다.**
12. 동영상을 보다가 옆 사진으로 갔다 **돌아오면 보던 위치에서 이어진다.**
13. 재생 중 **전화가 오면 멈춘다.**
14. 재생 중에는 **화면이 꺼지지 않고**, 멈추면 다시 꺼진다.
15. 끝까지 재생되면 **마지막 프레임에서 멈춘다.** 반복하거나 다음 페이지로 넘어가지 않는다.
16. 동영상을 **공유**하면 받는 앱에 동영상으로 전달된다(`image/*`가 아니다).
17. 재생 중인 동영상을 **삭제**해도 크래시하지 않고, 목록에서 빠지며 다음 항목으로 넘어간다.
18. 지원하지 않는 코덱이면 **오류 문구와 "다른 앱으로 열기"** 가 나오고, 눌렀을 때 예전처럼 외부 앱이 뜬다.
19. **원격(SFTP/SMB) 폴더의 동영상**은 지금처럼 외부 앱으로 열린다. 사진을 넘길 때 건너뛴다.
20. **사진만 있는 폴더의 동작이 이전과 완전히 같다** — 확대, 좌우 넘김, 탭 토글, 삭제·공유.

## 부록. 확정된 결정 기록

| # | 질문 | 결정 |
|---|---|---|
| D1 | 동영상 전용 뷰어를 따로 만들 것인가 | **만들지 않는다. 기존 이미지 뷰어에 통합한다.** 08번 미디어 모드가 사진과 동영상을 한 격자에 놓았는데 뷰어만 갈라지면 그 방향과 어긋난다. 앱 바·몰입 모드·삭제·공유를 그대로 물려받는 이득도 크다. 대가로 기존 뷰어 코드를 건드리므로 수용 기준 20번으로 회귀를 막는다 |
| D2 | 재생 엔진 | **Media3(ExoPlayer)를 새로 넣는다.** 플랫폼 `MediaPlayer`는 새 의존성이 없다는 것이 유일한 장점인데, 제조사별 편차가 있고 커스텀 소스 확장이 어렵다. D3을 나중에 뒤집으려면 커스텀 `DataSource`가 필요한데, 그 길이 열려 있는 쪽을 고른다 |
| D3 | 어느 경로까지 앱에서 재생하는가 | **로컬과 SAF 문서만.** 원격·아카이브는 지금처럼 외부 앱. 목적("폰으로 찍은 동영상")에 충분하고, 범위가 명확하다. 확장하려면 `DataSource` 하나를 더 만든다 (§3) |
| D4 | 매니페스트에 `video/*` 인텐트 필터를 넣을 것인가 | **넣지 않는다.** 다른 앱의 선택지에 끼어들면 사진처럼 좌우로 넘길 목록이 없는 단독 재생이 되어, 이 뷰어의 강점이 없는 채로 노출된다. 필요해지면 한 줄로 추가할 수 있다 |
| D5 | 동영상 페이지에 도착하면 자동 재생할 것인가 | **자동 재생한다.** 갤러리 앱의 보편적 동작이다. 훑을 때 소리가 튀는 문제는 "페이지가 완전히 멈춘 뒤에 시작"으로 막는다 (§5.1) |
| D6 | 재생 컨트롤을 직접 만들 것인가 | **기본 컨트롤을 쓰고 테마 색상만 맞춘다.** 슬라이더 드래그·버퍼링 구간 표시·재생 위치 갱신·시간 표기를 직접 구현하면 값어치에 비해 손이 많이 가고, 미묘한 버그가 나기 쉬운 영역이다. 모양이 아쉬우면 나중에 바꾼다 |
| D7 | 세부 정보를 기존 파일 속성 대화상자로 띄울 것인가 | **뷰어 안 오버레이 시트로 만든다.** 속성 대화상자는 한 줄이면 되지만 전체 화면을 덮고 재생이 끊긴다. 그리고 코덱·프레임 레이트가 없는데, 폰 영상에서는 그 둘이 실제로 궁금한 항목이다. 기존 탭은 그대로 둔다 |
| D8 | 재생 위치를 앱 재시작 뒤에도 기억할 것인가 | **기억하지 않는다.** 뷰어 세션 안에서만 기억한다(§5.4). 영구 저장은 저장소·정리 정책이 따라붙는데 얻는 것이 적다 |
| D9 | 음소거·반복 재생·다음 동영상 자동 재생을 넣을 것인가 | **넣지 않는다.** 요청된 것은 슬라이더·속도·세부 정보 셋이다. 쓸 곳이 정해지지 않은 기능으로 컨트롤을 채우지 않는다 |
| D10 | 프레임 단위 이동·구간 반복 | **이번 범위 아님.** 테스트 데이터가 골프 스윙 영상인 것을 보면 언젠가 필요해질 가능성이 높지만, 이번 요청은 셋으로 명확했다. `0.25×` 배속이 그 자리를 어느 정도 메운다. 필요해지면 이 문서를 개정한다 |
| D11 | 액티비티 이름을 바꿀 것인가 | **바꾼다.** `MediaViewer*`. 08번에서 "Photo 모드 → 미디어 모드"로 정리한 것과 같은 이유다. 사진만 다루는 이름으로 남겨 두면 나중에 코드를 읽는 사람이 오해한다. 기계적 변경이라 위험이 낮다 |
| D12 | 동영상 페이지에서 아래로 스와이프해 닫는 제스처를 넣을 것인가 | **이번 범위 아님.** 그 제스처는 `feature/swipe-down`의 작업이고 이 브랜치(`feature/media-view-mode`에서 분기)에는 들어있지 않다. 같은 제스처를 여기서 따로 구현하면 두 브랜치를 합칠 때 충돌한다. **두 작업이 합쳐진 뒤에** 동영상 페이지에도 적용할지 그때 정하고, 하기로 하면 이 문서를 개정한다 |

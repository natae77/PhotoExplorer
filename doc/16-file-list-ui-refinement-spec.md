# 16. 파일 목록 화면 후속 개선 기획서

14·15번에서 완성한 즐겨찾기·경로 바·노란 폴더 UI를 실제 기기에서 사용한 뒤 발견한
시각적 밀도와 정보 부족을 다듬는다. 이번 개선의 중심은 **상단 배경색·경로 바 아래 여백**, **폴더
아이콘 형태와 MEDIA 크기**, **선택 작업 아이콘**, **LIST 보조 정보**, **현재 폴더 제목**이다.

- 작성일: 2026-09-11
- 프로젝트: **PhotoExplorer** (`natae77/PhotoExplorer`, `zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 기준 브랜치: `feature/file-list-ui-refresh`
- 기준 커밋: `32c96c7f`
- 상태: **초안** — 아래 권장 구성을 구현 기준으로 제안

14번의 완료 범위를 다시 쓰는 문서가 아니라, 실기 검증 뒤 시작하는 별도 후속 개선이다.
14번에서 비목표였던 행 보조 정보와 툴바 제목 변경은 이 문서부터 새 목표가 된다.

## 1. 참고 화면과 가져올 요소

| [My Files 선택 화면](../PersonalDev/ScreenShot/Screenshot_20260911_122053_My%20Files.jpg) | 폴더+화살표 형태의 이동, 겹친 사각형 형태의 복사, 윤곽선 휴지통 형태의 삭제 아이콘 |

참고 앱의 자산을 추출하거나 그대로 포함하지 않는다. 같은 시각 문법을 따르는
PhotoExplorer용 벡터 경로를 직접 만들고, 기존 테마·선택·비활성 상태를 유지한다.

## 2. 목표와 비목표

### 2.1 목표

1. MEDIA가 최신 위치에 있을 때 보이는 앱 상단 배경색을 LIST·GRID에도 동일하게 적용하고,
   경로 바와 첫 파일 행 사이에 즐겨찾기 칩과 경로 바 사이에서 느껴지는 만큼의 여백을 둔다.
2. 폴더 아이콘을 My Files의 사진앨범 폴더처럼 앞판·상단 탭·안쪽 밝은 선이 보이는 형태로 바꾼다.
3. MEDIA의 폴더 아이콘이 타일을 가득 채우지 않도록 적절한 고정 크기로 줄인다.
4. 파일 선택 시 상단에 표시되는 이동·복사·삭제 아이콘을 참고 화면과 같은 의미가 즉시 읽히는 형태로 바꾼다.
5. LIST에서 폴더와 파일 모두 최신 수정 시각을 표시하고, 폴더에는 바로 아래 항목 수,
   일반 파일에는 파일 크기를 함께 표시한다.
6. 기본 툴바의 고정 제목 `파일` 대신 현재 폴더의 사용자 표시 이름을 보여 준다.

### 2.2 비목표

- 선택 작업 영역을 상단에서 My Files처럼 화면 아래 캡슐 바로 이동
- 선택 작업에 공유·더보기 버튼을 항상 노출하도록 메뉴 구조 재설계
- DCIM·Download처럼 폴더 종류별 카메라·다운로드 배지 추가
- 폴더 내부를 재귀 순회해 전체 하위 파일 수 계산
- GRID·MEDIA 타일에 수정 시각·파일 크기 추가
- 날짜 형식이나 단위 형식에 대한 새 사용자 설정 추가
- 기존 `⋮` 항목 메뉴 제거

## 3. 완성 화면 구조

```text
┌────────────────────────────────────────┐
│ 메뉴  현재 폴더 이름        검색  정렬 ⋮ │
│        폴더·파일 개수                  │
├────────────────────────────────────────┤
│ [즐겨찾기 1] [즐겨찾기 2] […]          │
│   현재 위치 > 하위 폴더                │  회색 경로 바
│                                        │  8dp 간격
│ [폴더]  사진앨범                    ⋮  │
│         9월 2일 오전 9:06 · 17개       │
│         ─────────────────────────────  │
│ [파일]  IMG_20260911_122053.jpg      ⋮  │
│         9월 11일 오후 12:20 · 3.8 MB   │
└────────────────────────────────────────┘
```

위 예시에서 `⋮`는 현재 항목별 메뉴를 뜻한다. 사용자 표현의 `:`는 이 세로 점 메뉴를
가리키는 것으로 해석하며, 기능과 48dp 터치 영역을 그대로 유지한다.

## 4. 상세 요구사항

### 4.1 앱 상단 배경색 통일과 경로 바 아래 간격

#### 에뮬레이터 확인 결과

Pixel_8 API 36 에뮬레이터의 M3 밝은 테마에서 같은 APK·경로를 캡처하고, 텍스트나 그림자가
없는 동일 좌표의 픽셀을 비교했다.

| 상태 | 앱 상단 배경 | 경로 바 내부 |
|---|---|---|
| LIST, 목록 맨 위 | `#FAF8FF` | `#F1F3F4` |
| MEDIA, 자동으로 이동한 최신 항목 위치 | `#EEEDF4` | `#F1F3F4` |
| MEDIA, 사용자가 목록 맨 위로 스크롤 | `#FAF8FF` | `#F1F3F4` |

경로 바 자체는 세 상태에서 정확히 같은 색이다. 달라지는 곳은 툴바, 즐겨찾기 주변, 경로 바
바깥을 포함한 **앱 바 전체 표면**이다. MEDIA는 진입 시 최신 항목으로 자동 스크롤되므로
`liftOnScroll`의 lifted 상태가 즉시 활성화되고, elevation overlay가 앱 바 표면을
`#EEEDF4`로 바꾼다. 그래서 보기 모드에 따라 색이 바뀌는 것처럼 보인다.

#### 최종 색 규칙

사용자가 선호한 MEDIA 최신 위치의 색을 기준으로 삼는다.

| 항목 | 규칙 |
|---|---|
| 기준 상단색 | 각 테마에서 현재 lifted app bar가 표시하는 surface 색. M3 밝음 실측 기준 `#EEEDF4` |
| 적용 범위 | 상태 표시줄 아래 앱 바, 기본 툴바, 즐겨찾기 바 주변, 경로 바 바깥 배경, overlay toolbar |
| LIST·GRID·MEDIA | 같은 테마라면 동일한 최종 상단 배경색 |
| 스크롤 | 맨 위·중간·끝에서 배경색 변화 없음 |
| elevation | 스크롤 위치를 알리는 그림자/elevation 변화는 유지할 수 있지만 fill 색은 바뀌지 않음 |
| 경로 바 | 밝음 `#F1F3F4`, 어두움·검정 야간 `#303134`를 그대로 유지 |
| 선택·검색 | 선택 overlay와 검색 상태에서도 주변 상단 fill이 같은 기준색을 유지 |
| 테마 | M2/M3, 밝음·어두움·검정 야간마다 해당 테마의 lifted surface를 기준으로 실측·검증 |

밝은 테마에 `#EEEDF4`를 무조건 하드코딩하기보다 현재 테마의 elevated/lifted surface를
안정적으로 해석하는 전용 `file_list_app_bar_background` 색 또는 theme attribute를 둔다.
`liftOnScroll`이 elevation을 바꾸더라도 배경 drawable에 overlay가 다시 합성되어 fill까지
변하지 않도록 한다. 기본 툴바와 선택 overlay toolbar도 같은 배경을 공유한다.

현재 경로 바의 둥근 하단과 RecyclerView 첫 행이 바로 붙어 있다. 경로 바 아래에 **8dp**의
명시적 여백을 추가한다.

| 간격 항목 | 규칙 |
|---|---|
| 크기 | 8dp |
| 위치 | 경로 바의 바깥쪽 아래. 회색 배경 내부 padding이 아님 |
| 색 | 앱 바/목록의 기존 배경색이 드러남 |
| 즐겨찾기 0개 | 같은 8dp 유지 |
| 스크롤 | 경로 바와 함께 기존 앱 바 스크롤 정책을 따름 |
| 넓은 화면 | 파일 목록 콘텐츠 폭 안에서 동일하게 적용 |

실기 화면에서 즐겨찾기 칩의 시각적 하단과 경로 바 사이가 약 8dp로 읽히므로, 같은 리듬을
아래에도 반복한다. RecyclerView의 각 행이나 빈 화면 전체에 padding을 추가하지 않는다.

### 4.2 폴더 아이콘 형태

LIST·GRID·MEDIA가 같은 계열의 새 폴더 실루엣을 공유한다.

- 아래쪽 앞판은 모서리가 부드러운 노란 직사각형에 가깝게 만든다.
- 상단 시작 쪽에는 낮고 넓은 폴더 탭을 둔다.
- 앞판 상단에는 밝은 노랑 또는 흰색 반투명 한 줄을 넣어 참고 화면의 겹친 판 구조를 표현한다.
- 외곽선만 있는 아이콘으로 돌아가지 않고 `file_icon_yellow` 계열의 채움색을 유지한다.
- LIST의 24dp 아이콘과 GRID·MEDIA 썸네일은 같은 실루엣을 사용하되, 작은 크기에서 선이
  뭉개지지 않도록 필요하면 별도 viewport 경로를 둔다.
- 선택, 비활성화, 클립보드 대기, 앱·심볼릭 링크 badge의 기존 alpha와 상태 처리는 유지한다.
- RTL에서도 폴더 탭 방향은 파일 아이콘의 고유 형태로 유지하며 자동 반전하지 않는다.

색만 같고 단순한 사각 폴더였던 현재 벡터보다 형태 인지가 쉬워야 한다. 다만 사진앨범이라는
특정 폴더에만 다른 아이콘을 적용하지는 않는다.

### 4.3 MEDIA 폴더 아이콘 크기

MEDIA의 `directoryThumbnailImage`는 현재 정사각형 타일 전체를 차지해 폴더 모양이 과도하게
커 보인다. 다음을 기본값으로 한다.

| 항목 | 규칙 |
|---|---|
| 표시 크기 | **56dp × 56dp** |
| 정렬 | 정사각형 타일의 가로·세로 중앙 |
| 타일 크기 | 기존 약 112dp 목표 폭과 span 계산 유지 |
| 폴더 이름 | 기존 하단 한 줄 이름과 scrim 유지 |
| 일반 미디어 | 썸네일의 edge-to-edge 표시 유지 |

56dp는 목표 타일 폭의 절반으로, 폴더임을 즉시 알아볼 수 있으면서 타일을 가득 채우지 않는다.
실기에서 48dp는 작고 64dp는 큰 경우에만 4dp 단위로 조정하되, 최종 값은 이 문서에 기록한다.
GRID의 폴더 썸네일 크기는 이번 변경 대상이 아니다.

### 4.4 선택 작업 아이콘

선택 모드의 위치와 동작은 그대로 두고 `file_list_select`에서 사용하는 세 아이콘만 전용 벡터로
교체한다.

| 동작 | 새 모양 | 유지할 동작 |
|---|---|---|
| 이동(현재 `action_cut`) | 둥근 폴더 윤곽 안에서 오른쪽을 가리키는 화살표 | 잘라내기 상태로 전환한 뒤 목적지에서 붙여넣는 기존 흐름 |
| 복사 | 앞뒤로 겹친 두 개의 둥근 사각형 윤곽 | 복사 상태와 archive의 추출 아이콘 대체 규칙 |
| 삭제 | 뚜껑·손잡이·몸체가 분리되어 읽히는 윤곽선 휴지통 | 기존 확인 대화상자와 읽기 전용 숨김 규칙 |

- 아이콘은 24dp viewport, 최소 2dp 상당의 일정한 stroke 느낌으로 직접 제작한다.
- 색은 `?colorControlNormal`을 사용해 M2·M3, 밝음·어두움 테마에 대응한다.
- 상단 툴바의 배치, 메뉴 ID, 단축키, content description은 유지한다.
- 전역 `cut`, `copy`, `delete` 아이콘을 바꾸지 않고 파일 목록 선택 메뉴 전용 자산을 사용한다.
- archive 항목을 선택해 복사 동작이 `추출`로 바뀌는 경우에는 기존 추출 아이콘을 유지한다.

참고 화면의 하단 작업 바 자체는 이번 범위가 아니다. 위치까지 옮기면 작은 화면, 키보드,
선택 모드, 기존 붙여넣기 bottom action mode 사이의 정책을 별도로 설계해야 한다.

### 4.5 LIST의 수정 시각·개수·크기

#### 권장 구성

기존 `⋮` 메뉴를 오른쪽에 고정하고, 이름 아래의 보조 정보 한 줄에 두 값을 합친다.

```text
[폴더]  사진앨범                              ⋮
         9월 2일 오전 9:06 · 17개

[파일]  IMG_20260911_122053_My Files.jpg      ⋮
         9월 11일 오후 12:20 · 3.8 MB
```

이 구성이 날짜를 왼쪽, 개수나 크기를 오른쪽 끝에 따로 두는 방식보다 적합한 이유는 다음과 같다.

1. 우측 48dp `⋮` 터치 영역과 숫자가 겹치지 않는다.
2. 폴더명이나 파일명이 긴 좁은 화면에서도 정보의 읽기 순서가 일정하다.
3. 현재의 2줄 72dp LIST 행과 `descriptionText`를 재사용할 수 있다.
4. TalkBack이 이름 다음에 한 문장으로 보조 정보를 읽을 수 있다.

#### 표시 규칙

| 항목 | 두 번째 줄 |
|---|---|
| 폴더 | `{최종 수정 시각} · {바로 아래 항목 수}개` |
| 일반 파일 | `{최종 수정 시각} · {사람이 읽는 파일 크기}` |
| 심볼릭 링크 폴더 | 링크 대상이 정상 폴더면 폴더 규칙, 깨졌거나 열 수 없으면 날짜만 표시 |
| archive 내부의 폴더 | 해당 archive provider가 열거를 지원하면 직접 하위 항목 수, 실패하면 날짜만 표시 |
| 개수 계산 중 | 우선 수정 시각만 표시하고, 완료 시 ` · N개`를 붙임 |
| 개수 계산 실패 | `0개`로 오인시키지 않고 수정 시각만 표시 |

날짜는 `lastModifiedTime()`과 기존 `formatShort(context)`를 사용한다. 파일 크기는 기존
`formatHumanReadable(context)`를 사용해 앱의 언어·단위 형식을 유지한다. 구분자는 일반
가운데점 ` · `을 사용하며 번역 문자열 자원으로 둔다.

#### 폴더 개수의 의미

- **재귀 파일 수가 아니라 바로 아래의 파일과 폴더를 합친 항목 수**다.
- 숨김 파일 표시 설정과 무관하게 실제 directory stream이 반환한 직접 하위 항목 수를 기본으로 한다.
- 권한 때문에 일부만 열거된 값을 확정 개수처럼 표시하지 않는다.
- 폴더 수정 시각은 내부에서 가장 최근에 수정된 파일을 다시 계산한 값이 아니라 그 폴더 자체의
  `lastModifiedTime()`이다.

#### 성능과 수명 주기

폴더마다 메인 스레드에서 directory stream을 열면 긴 목록과 원격 저장소에서 심각한 지연이
생길 수 있으므로 다음 원칙을 지킨다.

1. 개수 계산은 worker dispatcher에서 실행한다.
2. 화면에 bind된 폴더부터 요청하고 동시 작업 수를 제한한다.
3. `Path` 기준 메모리 캐시를 두고 같은 목록의 재bind·스크롤에서는 재계산하지 않는다.
4. 새로고침, 파일 작업 완료, provider 변경 감지 시 관련 경로 캐시를 무효화한다.
5. ViewHolder 재사용 전에 요청 경로가 여전히 같은지 확인해 다른 행에 늦은 결과가 붙지 않게 한다.
6. 화면을 떠나거나 보기 모드를 바꾸면 불필요한 요청을 취소한다.
7. 원격 provider의 지연·오류가 파일 목록 자체의 로딩 성공을 실패로 바꾸지 않게 한다.

### 4.6 툴바에 현재 폴더 이름 표시

기본 상태의 툴바 제목은 고정 문자열 `파일`이 아니라 breadcrumb가 현재 선택 경로에 사용하는
**사용자 표시 이름**으로 갱신한다.

| 경로 상태 | 제목 |
|---|---|
| 일반 폴더 | 현재 폴더명. 예: `사진앨범`, `Camera` |
| 등록된 저장소 루트 | navigation root의 지역화된 이름. 예: `디바이스 저장공간` |
| archive 루트 | archive 파일명 |
| 표시 이름을 얻을 수 없는 루트 | 기존 `파일` 문자열로 fallback |
| 검색 중 | 현재 폴더 제목 유지. 검색 입력 UI가 기존 방식으로 위에 표시됨 |
| 선택 중 | overlay toolbar에는 기존처럼 `N개 선택됨`; 선택 해제 뒤 현재 폴더 제목 복원 |
| 로딩·오류 | 제목은 현재 폴더명, subtitle만 기존 `로드 중`·`오류` 규칙 적용 |

`Path.fileName`만 사용하면 저장소 루트가 `/`로 보일 수 있으므로 `BreadcrumbData`의 선택된
`nameProducer`를 제목의 단일 기준으로 재사용한다. 경로 이동, 뒤로가기, 즐겨찾기 이동,
화면 회전 후에도 같은 observer에서 갱신한다.

## 5. 화면 상태와 접근성

1. LIST의 이름과 보조 정보는 각각 한 줄이며 긴 문자열은 끝에서 말줄임한다.
2. `⋮` 버튼은 최소 48dp 터치 영역과 기존 content description을 유지한다.
3. 폴더 보조 정보가 비동기로 갱신되어도 항목 높이와 스크롤 위치는 바뀌지 않는다.
4. TalkBack은 `이름 → 수정 시각 → 항목 수/파일 크기 → 메뉴` 순서로 읽을 수 있어야 한다.
5. 선택 작업 아이콘은 모양만으로 구분되며 기존 메뉴 title이 접근성 이름으로 남는다.
6. 새 폴더의 밝은 내부 선은 밝은·어두운·검정 야간에서 노란 앞판과 구분되어야 한다.
7. 글꼴 크기를 키웠을 때 보조 정보는 한 줄 말줄임하되 `⋮`가 밀려나지 않는다.
8. RTL에서는 텍스트와 메뉴 위치가 논리적 start/end로 반전되지만 폴더 glyph 자체는 반전하지 않는다.

## 6. 데이터·호환성

- 설정 형식이나 마이그레이션을 추가하지 않는다.
- 기존 정렬 기준과 정렬 결과를 바꾸지 않는다.
- 폴더 개수는 표시용 파생 데이터이며 `FileItem`의 동등성·DiffUtil 키에 포함하지 않는다.
- 앱 재시작 뒤 디스크 캐시를 유지할 필요는 없다.
- 접근 불가능한 폴더의 개수 실패가 전체 목록의 오류 화면으로 전파되지 않아야 한다.
- SAF, SMB, SFTP, FTP, WebDAV, archive 등 모든 provider에서 개수 미표시 fallback이 안전해야 한다.

기존 프로젝트의 번역 fallback 정책을 따른다.

## 8. 수용 기준

1. 동일 테마에서 앱 바의 같은 빈 지점을 비교했을 때 LIST·GRID·MEDIA의 최종 ARGB가 같다.
2. 각 보기에서 맨 위와 스크롤된 lifted 상태의 앱 바 fill ARGB가 같고, 그림자만 달라질 수 있다.
3. M3 밝은 테마 기준 상단 배경은 MEDIA 최신 위치에서 확인한 `#EEEDF4`와 같다.
4. 경로 바 내부는 보기와 스크롤 상태에 관계없이 밝음 `#F1F3F4`, 야간 `#303134`를 유지한다.
5. 경로 바 아래와 첫 콘텐츠 사이에 8dp 공간이 보이고 위쪽의 시각적 간격과 균형을 이룬다.
6. 즐겨찾기 0개와 다수 모두에서 경로 바 아래 간격이 동일하다.
7. LIST·GRID·MEDIA 폴더가 앞판·탭·밝은 내부 선을 가진 같은 계열의 노란 폴더로 보인다.
8. MEDIA 폴더 아이콘은 56dp로 중앙에 놓이고 타일 가장자리에 닿지 않는다.
9. 사진·동영상 MEDIA 썸네일 크기에는 변화가 없다.
10. 선택 모드의 이동은 폴더+화살표, 복사는 겹친 사각형, 삭제는 윤곽선 휴지통으로 보인다.
11. 선택 작업의 기존 실행 결과, 읽기 전용 처리, archive 추출 전환에 회귀가 없다.
12. LIST 폴더는 `수정 시각 · N개`, 파일은 `수정 시각 · 크기` 형식으로 보인다.
13. 폴더 계산 중과 실패 시 날짜가 먼저 안전하게 보이고 잘못된 `0개`가 표시되지 않는다.
14. 빠르게 스크롤해도 다른 폴더의 개수가 재사용된 행에 잘못 나타나지 않는다.
15. 수백 개 폴더나 느린 원격 저장소에서도 목록 스크롤과 최초 표시가 개수 계산 때문에 막히지 않는다.
16. `⋮` 메뉴가 유지되고 이름·보조 정보와 겹치지 않으며 기존 메뉴를 연다.
17. 툴바 제목은 경로 이동 직후 현재 폴더 표시 이름으로 바뀐다.
18. 저장소·archive 루트에서도 `/` 같은 내부 이름 대신 사용자 친화적인 이름이나 `파일` fallback이 보인다.
19. 검색·선택을 닫은 뒤 현재 폴더 제목이 정확히 복원된다.
20. M2/M3, 밝음·어두움·검정 야간, LIST/GRID/MEDIA, 접힘·펼침에서 레이아웃이 깨지지 않는다.
21. TalkBack과 큰 글꼴에서 정보 순서와 모든 48dp 터치 영역이 유지된다.

| 범주 | 최소 확인 |

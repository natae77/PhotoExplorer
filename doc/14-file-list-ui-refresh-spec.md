# 14. 파일 목록 화면 정리 기획서

파일 목록에서 **현재 위치와 폴더의 경계를 더 분명하게 보여 주고**, 자주 쓰는 폴더로
곧바로 이동할 수 있는 즐겨찾기 바로가기를 경로 위에 둔다.

이 문서는 *무엇을 만들 것인가*만 정의한다. 파일별 수정 방법과 작업 순서는 후속 구현
계획서에서 다룬다.

- 작성일: 2026-09-10
- 프로젝트: **PhotoExplorer** (`natae77/PhotoExplorer`, `zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 기준 브랜치: `feature/file-list-ui-refresh`
- 기준 커밋: `6c0d74f1`
- 상태: **확정** — §3의 다섯 항목을 구현 대상으로 삼는다

**개정 규칙** — 요구가 바뀌면 새 문서를 만들지 않고 본문을 직접 고친 뒤 아래 표에 남긴다.

| 2차 | 2026-09-10 | 리뷰 반영 — 경로 이동 시 선택 해제, 칩 최대 폭, 경로 일치·중복 선택, 길게 누르기 대상, 경로 바 테마 색 확정 |

## 2. 목표 / 비목표

### 2.1 목표

1. 목록 모드에서 폴더 행의 경계를 얇은 구분선으로 알아보기 쉽게 한다.
2. breadcrumb를 회색 배경의 독립된 **경로 바**로 보이게 한다.
3. 경로의 시작점을 화면 왼쪽에 맞춰 현재 위치를 빠르게 읽게 한다.
4. 모든 파일 목록 보기에서 폴더를 노란색 채움 아이콘으로 일관되게 표시한다.
5. 기존 즐겨찾기를 경로 바 위의 가로 바로 노출해 한 번의 탭으로 이동하게 한다.
6. 밝은 테마·어두운 테마, 좁은 폰·넓은 폴더블 화면에서 같은 기능을 유지한다.

### 2.2 비목표

- 참고 앱의 큰 저장공간 제목, 정렬 영역, 항목 개수, 날짜 형식 등 **전체 화면 복제**
- DCIM에는 카메라, Download에는 내려받기 표시를 넣는 **폴더별 전용 아이콘**
- 즐겨찾기를 새로 저장하는 별도 데이터 형식
- 즐겨찾기 추가·이름 변경·삭제·순서 변경 방식의 재설계
- 파일 아이콘이나 미디어 썸네일의 색상 변경
- 목록의 행 높이, 글꼴, 보조 정보 형식, 정렬 방식 변경
- 그리드·미디어 타일 사이에 구분선 추가
- 홈 아이콘이나 새로운 breadcrumb 계층을 경로 바에 추가

## 3. 상세 요구사항

### 3.1 폴더 행 구분선

구분선은 **목록 보기(`LIST`)의 폴더 행 아래**에 표시한다. 그리드 보기와 미디어 보기에는
표시하지 않는다.

| 항목 | 규칙 |
|---|---|
| 두께 | 1dp |
| 시작점 | 폴더 아이콘 영역을 지난 뒤, 이름·설명 텍스트가 시작하는 위치 |
| 끝점 | 행 오른쪽의 콘텐츠 여백 전까지 |
| 색 | 현재 테마의 표준 divider 색. 밝은 테마와 어두운 테마에서 각각 자동 대응 |
| 표시 대상 | 폴더 행 아래. 마지막 폴더와 다음 파일 사이에도 표시 |
| 선택 상태 | 선택 배경과 ripple을 가리지 않아야 함 |

구분선 때문에 행 높이나 터치 영역이 늘어나서는 안 된다. 선은 행의 경계에 겹쳐 그리거나
기존 높이 안에 배치한다.

파일과 파일 사이에는 이번 요구로 새 구분선을 넣지 않는다. 폴더를 먼저 정렬하지 않는 설정에서도
각 폴더 행 바로 아래에만 선이 붙는 규칙은 같다.

### 3.2 회색 경로 바

현재 breadcrumb 기능은 그대로 유지하되, 전체 영역을 하나의 회색 바처럼 보이게 한다.

| 항목 | 규칙 |
|---|---|
| 바깥 여백 | 화면 시작·끝에서 16dp |
| 높이 | **36dp**. 즐겨찾기 칩의 보이는 높이와 맞춘다 |
| 모양 | 모서리가 둥근 직사각형. 완전한 캡슐 형태를 기본으로 함 |
| 밝은 테마 | 경로 바 전용 색 `#F1F3F4` |
| 어두운 테마 | 경로 바 전용 색 `#303134` |
| 검정 야간 모드 | 어두운 테마와 같은 `#303134`. 검은 본문 배경과 명확히 구분 |
| 선택 경로 | 기존 활성색과 글자 강조 유지 |
| 이전 경로 | 기존 보조 글자색 유지 |

경로 바 배경은 `file_list_path_bar_background`처럼 용도가 드러나는 전용 색 자원으로 둔다.
밝은 테마와 야간 테마에서 위 값을 각각 제공하며, `colorSurface`를 직접 배경으로 사용하지
않는다. 특히 검정 야간 모드의 `colorSurface`는 검정이므로 이를 그대로 쓰면 바와 본문이
구분되지 않는다.

Material Design 3의 동적 색상을 사용하더라도 이번 경로 바의 중성 회색은 위 전용 자원을
유지한다. 활성 breadcrumb와 선택된 즐겨찾기 칩에만 사용자의 강조색을 반영한다. 글자색은
기존 `textColorPrimary`·`textColorSecondary` 계열을 유지하고, 경로 바 배경과의 대비가
WCAG AA 기준(일반 크기 텍스트 4.5:1 이상)을 만족해야 한다.

breadcrumb의 기존 기능은 바뀌지 않는다.

- 경로 조각을 누르면 해당 상위 폴더로 이동한다.
- 길게 누르면 경로 복사와 새 작업에서 열기 메뉴가 뜬다.
- 경로가 폭보다 길면 가로로 스크롤할 수 있다.
- 새 폴더로 이동하면 선택된 경로 조각이 보이도록 자동 스크롤한다.

### 3.3 경로 왼쪽 정렬

경로 바 안의 첫 번째 보이는 경로 조각은 **바의 왼쪽 안쪽 여백에서 시작**한다. 현재의 큰
콘텐츠 시작 여백에 맞추지 않는다.

- LTR 언어에서는 왼쪽, RTL 언어에서는 오른쪽에서 시작한다. 즉 구현 기준은 물리적인
  `left`가 아니라 논리적인 `start`이다.
- 기본 안쪽 여백은 12dp로 한다.
- 경로가 짧아도 가운데로 이동하지 않는다.
- 경로가 길 때 선택된 조각을 보이게 하는 기존 자동 스크롤은 왼쪽 정렬보다 우선한다.
  이는 정렬 변경이 아니라 **현재 위치의 가시성 보장**이다.

### 3.4 노란색 채움 폴더 아이콘

폴더는 회색 윤곽선 대신 **노란색으로 채워진 폴더 실루엣**으로 표시한다. 새 비트맵을 넣지 않고
해상도에 독립적인 벡터 자산을 사용한다.

| 보기 | 적용 |
|---|---|
| 목록(`LIST`) | 24dp 폴더 아이콘을 노란색 채움 형태로 표시 |
| 바둑판(`GRID`) | 폴더 썸네일 자리에 쓰는 폴더 벡터를 같은 계열로 표시 |
| 미디어(`MEDIA`) | 폴더 타일의 폴더 벡터를 같은 계열로 표시 |

색은 프로젝트에 이미 있는 `file_icon_yellow` 계열을 사용한다. 밝은 테마에서는 짙은 노랑,
어두운 테마에서는 더 밝은 노랑이 적용되므로 별도의 색을 새로 정의하지 않는 것을 기본으로 한다.

폴더를 구분하는 핵심은 **모양**이므로 색을 인지하기 어려운 사용자도 파일과 혼동하지 않아야 한다.
비활성화·선택·클립보드 상태에서 기존 alpha 및 상태 표현도 유지한다.

### 3.5 즐겨찾기 바로가기 바

기존 `Settings.BOOKMARK_DIRECTORIES` 목록을 그대로 화면에 보여 준다. 탐색 서랍과 설정 화면의
즐겨찾기와 동일한 데이터이며, 별도의 복사본이나 동기화 로직을 만들지 않는다.

#### 위치와 모양

- 기존 툴바 아래, 경로 바 위에 배치한다.
- 한 줄짜리 가로 목록이며 항목이 넘치면 좌우로 스크롤한다.
- YouTube Music의 상단 항목처럼 각각 둥근 직사각형 칩으로 표시한다.
- 칩에는 즐겨찾기 이름만 한 줄로 표시하고, 긴 이름은 한 항목 안에서 말줄임한다.
- 칩 하나의 최대 폭은 **200dp**로 한다. 이름과 좌우 안쪽 여백을 포함한 전체 칩 폭의
  상한이며, 이를 넘는 이름은 끝에서 말줄임한다.
- 표시 이름은 기존 규칙대로 사용자 지정 이름이 있으면 그것을, 없으면 폴더 이름을 쓴다.
- 칩의 최소 터치 높이는 48dp를 확보한다.
- 목록 순서는 즐겨찾기 설정에 저장된 순서를 그대로 따른다.

#### 동작

| 입력/상태 | 동작 |
|---|---|
| 칩 탭 | 같은 작업 안에서 해당 경로로 즉시 이동 |
| 칩 길게 누르기 | 탐색 서랍에서 즐겨찾기를 길게 누를 때와 같은 **해당 항목의 개별 편집 대화상자**를 연다 |
| 현재 경로와 칩 경로가 같음 | `currentPath == bookmark.path`인 칩을 선택 상태로 강조 |
| 즐겨찾기 이름·순서·목록 변경 | 화면을 다시 열 필요 없이 바로 갱신 |
| 즐겨찾기 0개 | 바 전체를 숨겨 빈 세로 공간을 남기지 않음 |
| 접근할 수 없는 경로 | 기존 경로 이동의 오류 처리 방식을 그대로 사용 |

즐겨찾기 항목을 이 바에서 직접 끌어 순서를 바꾸거나, 칩 끝에 삭제 버튼을 붙이지 않는다.
관리는 기존 설정 화면에서 한다.

같은 경로를 이름만 달리해 여러 번 즐겨찾기한 경우에는 경로가 일치하는 **모든 칩**을 선택
상태로 표시한다. 선택 여부는 즐겨찾기 ID나 표시 이름이 아니라 위의 `Path` 동등성으로
판단한다.

## 4. 화면 상태별 규칙

### 4.1 검색과 선택 모드

- 검색 중에도 즐겨찾기 바와 경로 바는 현재처럼 앱 바 구조 안에 남는다.
- 여러 파일을 선택해 선택용 툴바가 나타나도 두 바의 표시 여부와 높이는 바뀌지 않는다.
- 칩이나 breadcrumb를 눌러 다른 경로로 이동할 때 검색을 닫고 선택한 파일을 모두 해제한
  다음 이동한다. 검색·선택 모드에서도 두 바는 활성 상태를 유지한다.
- 현재 경로와 같은 즐겨찾기 칩을 누르는 경우에는 실제 경로 이동이 없으므로 검색·선택
  상태를 바꾸지 않는다.

### 4.2 스크롤과 앱 바

즐겨찾기 바와 경로 바는 하나의 상단 탐색 영역이다. 기존 앱 바가 목록 스크롤에 따라 움직이는
정책을 함께 따른다. 둘 중 하나만 화면에 어색하게 남거나 겹치지 않아야 한다.

가로 스크롤 제스처는 다음처럼 분리한다.

- 즐겨찾기 바에서 가로 드래그: 즐겨찾기 칩 목록 이동
- 경로 바에서 가로 드래그: breadcrumb 이동
- 파일 목록에서 세로 드래그: 기존 목록 스크롤

### 4.3 넓은 화면과 탐색 서랍

폴더블을 펼치거나 태블릿에서 탐색 서랍이 고정되어도, 즐겨찾기와 경로 바는 **파일 목록 콘텐츠의
폭**을 기준으로 배치한다. 전체 기기 폭이나 탐색 서랍 아래로 뻗지 않는다.

### 4.4 테마

- 밝은 테마와 어두운 테마 모두 지원한다.
- Material Design 2/3 설정에 관계없이 기능과 배치는 같다.
- 사용자가 선택한 강조색은 활성 breadcrumb와 선택된 즐겨찾기 칩에 계속 반영한다.
- 경로 바는 밝은 테마에서 `#F1F3F4`, 어두운 테마와 검정 야간 모드에서 `#303134`를
  사용한다. 검정 야간 모드에서도 바가 본문 배경과 구분되어야 한다.

## 5. 데이터와 호환성

이번 기능은 기존 즐겨찾기 저장 형식과 경로 탐색 상태를 재사용한다.

- 설정 마이그레이션이 없어야 한다.
- 기존 즐겨찾기, 사용자 지정 이름, 순서가 그대로 나타나야 한다.
- 같은 경로를 이름만 달리해 여러 번 즐겨찾기한 경우에도 각각의 칩을 표시한다.
- 앱을 업데이트하거나 화면을 회전해도 즐겨찾기 데이터가 달라지지 않는다.
- 파일 목록의 보기 모드·정렬·경로별 설정에는 영향을 주지 않는다.

## 6. 접근성

1. 모든 즐겨찾기 칩은 최소 48dp 터치 영역을 갖는다.
2. 칩의 접근성 이름은 화면에 보이는 즐겨찾기 이름과 같게 한다.
3. 선택된 즐겨찾기는 색만 바꾸지 않고 Android의 선택 상태도 노출한다.
4. 경로 바의 글자와 배경은 밝은·어두운·검정 야간 테마에서 4.5:1 이상의 대비를 가져야 한다.
5. TalkBack 탐색 순서는 툴바 → 즐겨찾기 → breadcrumb → 파일 목록 순서가 된다.
6. 노란색을 구분하지 못해도 폴더 실루엣으로 파일과 구분할 수 있어야 한다.

## 7. 수용 기준

1. 목록 보기에서 각 폴더 행 아래에 텍스트 시작점부터 오른쪽까지 1dp 구분선이 보인다.
2. 파일 행에 이번 기능으로 추가된 구분선은 보이지 않는다.
3. breadcrumb 전체가 본문과 구분되는 둥근 회색 경로 바로 보인다.
4. 짧은 경로는 경로 바의 시작 쪽에 정렬되며 가운데에 뜨지 않는다.
5. 긴 경로의 모든 조각을 가로 스크롤로 확인하고 기존 방식대로 이동·길게 누를 수 있다.
6. 목록·바둑판·미디어 보기의 폴더가 모두 노란색 채움 아이콘으로 보인다.
7. 즐겨찾기가 툴바와 경로 바 사이에 한 줄 칩 목록으로 나타난다.
8. 즐겨찾기가 많으면 가로 스크롤되고 세로로 두 줄이 되지 않는다.
9. 즐겨찾기 칩을 누르면 같은 작업 안에서 그 경로로 이동한다.
10. 즐겨찾기 설정을 바꾸면 현재 화면의 칩 목록도 바로 갱신된다.
11. 즐겨찾기가 없으면 경로 바가 위로 당겨지고 빈 자리가 남지 않는다.
12. 칩은 이름과 좌우 여백을 합쳐 200dp를 넘지 않으며 긴 이름은 한 줄 끝 말줄임된다.
13. 현재 경로와 같은 경로를 가진 즐겨찾기 칩은 모두 선택 상태로 표시된다.
14. 다른 경로의 칩이나 breadcrumb를 누르면 기존 검색과 파일 선택이 해제된 뒤 이동한다.
15. 칩을 길게 누르면 해당 즐겨찾기의 개별 편집 대화상자가 열린다.
16. 밝은·어두운·검정 야간 테마에서 배경, 글자, divider, 노란 폴더가 모두 구분되고,
    경로 바의 일반 크기 글자는 배경과 4.5:1 이상의 대비를 갖는다.
17. 폴더블 접기·펼치기와 화면 회전 후에도 칩 및 경로의 레이아웃이 깨지지 않는다.
18. 기존 검색, 선택, 정렬, 보기 모드, 탐색 서랍, 경로 메뉴 동작에 회귀가 없다.

## 8. 구현 뒤 실기기에서 확인할 것

| # | 확인 항목 | 판단 기준 |
|---|---|---|
| 1 | 즐겨찾기 바와 경로 바가 함께 있을 때 상단이 너무 높지 않은가 | 경로 바가 36dp로 보이고 즐겨찾기 칩과 시각적 높이가 맞는지 확인 |
| 2 | 경로 바 회색의 명도 | 밝은 `#F1F3F4`, 어두운·검정 야간 `#303134`가 본문과 구분되고 글자 대비 4.5:1 이상 유지 |
| 3 | divider 시작점 | 아이콘 아래를 비운 참고 화면의 리듬과 맞는지 확인 |
| 4 | 노란 폴더의 명도 | 밝은 배경과 어두운 배경 모두에서 형태가 뭉개지지 않는지 확인 |
| 5 | 가로 제스처 충돌 | 즐겨찾기와 breadcrumb를 각각 스크롤할 때 폴더블의 뒤로가기 제스처와 과도하게 충돌하지 않음 |
| 6 | 매우 긴 즐겨찾기 이름 | 전체 칩 폭이 200dp를 넘지 않고 한 줄 끝 말줄임되는지 확인 |

실측에서 크기나 명도 조정이 필요하면 기능 규칙은 유지한 채 이 문서를 개정한다.

## 9. 결정 기록

| 결정 | 내용 | 이유 |
|---|---|---|
| D1 | 다섯 항목을 모두 필수 범위로 둔다 | 노란 폴더도 기존 벡터 자산을 바꾸는 방식으로 확실히 구현 가능 |
| D2 | 즐겨찾기는 기존 bookmark 데이터를 재사용한다 | 탐색 서랍·설정과 한 목록을 공유해 중복과 불일치를 막음 |
| D3 | 즐겨찾기 0개일 때 바를 숨긴다 | 기능이 없는 사용자에게 빈 상단 공간을 강요하지 않음 |
| D4 | 폴더 divider만 추가한다 | 사용자가 요청한 범위를 지키고 파일 목록 전체의 밀도를 불필요하게 바꾸지 않음 |
| D5 | 폴더별 카메라·다운로드 표시는 넣지 않는다 | 이번 목표는 일관된 노란 폴더이며 폴더 분류 체계는 별도 기능 |
| D6 | 논리적 start 정렬을 사용한다 | 한국어의 왼쪽 정렬 의도를 지키면서 RTL 언어 호환성 유지 |
| D7 | 칩 길게 누르기는 해당 항목의 기존 개별 편집 대화상자로 연결한다 | 탐색 서랍과 같은 동작을 재사용하고 대상 화면의 모호함을 없앰 |
| D8 | 경로 바와 칩 바는 기존 앱 바 스크롤 정책을 함께 따른다 | 상단 탐색 요소가 따로 움직이며 겹치는 상태를 방지 |
| D9 | 즐겨찾기 칩의 최대 폭은 200dp로 한다 | 좁은 화면에서 한 칩이 목록을 독점하지 않으면서 일반적인 폴더 이름은 충분히 표시 |
| D10 | 다른 경로로 이동하기 전에 검색과 파일 선택을 해제한다 | 이전 폴더의 선택 항목이 남아 잘못된 파일 작업 대상이 되는 것을 방지 |
| D11 | `currentPath == bookmark.path`인 모든 중복 칩을 선택한다 | 기존 탐색 서랍의 경로 비교 방식과 맞추고 같은 경로의 중복 즐겨찾기를 일관되게 표현 |
| D12 | 경로 바는 밝은 `#F1F3F4`, 야간 `#303134` 전용 색 자원을 쓴다 | M2·M3·검정 야간 모드에서 본문과의 구분을 보장하고 `colorSurface` 동일색 문제를 피함 |

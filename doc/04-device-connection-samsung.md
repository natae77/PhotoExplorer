# 04. 삼성 폰 ADB 연결 (자동 차단 문제)

## 증상

- 개발자 옵션과 USB 디버깅을 켰는데 "USB 디버깅을 허용하시겠습니까?" 팝업이 **안 뜬다**
- Android Studio: `Error running 'app'` (실제로는 대상 기기가 없다는 뜻)
- `adb devices` 에 폰이 **아예 안 나온다** (`unauthorized` 조차 아님)

## 진단 방법

### 1) adb 레벨

```bash
adb devices -l
```

- 목록에 없음 → USB/드라이버/폰 설정 문제
- `unauthorized` → 폰에서 승인만 하면 됨 (다른 문제)

### 2) Windows 장치 레벨 (PowerShell)

```powershell
Get-PnpDevice | Where-Object { $_.InstanceId -like "*VID_04E8*" } |
    Select-Object Status, Class, FriendlyName, InstanceId | Format-List
```

`VID_04E8` = 삼성. 이번 사례의 결과:

| 인터페이스 | 정체 | 드라이버 |
|---|---|---|
| MI_00 | MTP (파일 전송) | WPD — 정상 |
| MI_01 | 시리얼 포트 (COM3) | `usbser` (Microsoft) |
| — | **ADB 인터페이스** | **아예 없음** |

**ADB 인터페이스가 폰에서 노출되지 않는다** = 드라이버 문제가 아니라 폰 설정 문제.

> MTP가 동작한다는 것은 케이블에 데이터선이 살아 있다는 뜻이므로,
> 케이블 불량 가능성은 이 시점에 배제된다.
> MI_01의 COM3 시리얼은 삼성 기기가 원래 노출하는 별개 인터페이스로 무관하다.

## 원인: 삼성 자동 차단 (Auto Blocker)

One UI 6.0(Android 14)부터 추가된 보안 기능.
켜져 있으면 **USB 케이블을 통한 모든 명령을 차단**한다. ADB가 여기 해당된다.

증상 표시: `개발자 옵션`의 USB 디버깅 항목이 회색(dimmed)이 되고
**"보안 위험 자동 차단에서 차단함"** 이라고 적힌다.

### 해제

`설정` → `보안 및 개인 정보 보호` → `자동 차단` →
**`USB 케이블로 소프트웨어 업데이트 및 명령 차단`** 끄기

(자동 차단 전체를 끌 필요는 없다. 이 하위 항목 하나만.)

메뉴를 못 찾으면 `설정` 검색창에 **"자동 차단"**.

### 해제 후

1. 케이블 재연결
2. 폰 **화면 잠금 해제 상태**로 유지
3. "USB 디버깅을 허용하시겠습니까?" → `이 컴퓨터에서 항상 허용` → 허용

## dimmed 일 때 다른 원인들

| 원인 | 확인 |
|---|---|
| 개발자 옵션 마스터 토글 OFF | `개발자 옵션` 화면 **맨 위** 토글. 꺼져 있으면 하위 전부 dimmed |
| 절전/초절전 모드 | `설정` → `배터리` |
| Knox/MDM (회사 폰) | "관리자에 의해 사용 중지됨" 표시. 우회 불가 |
| 자녀 보호 (Family Link) | — |

## ADB로 접근 가능한 범위 (보안)

`adb`는 `uid=2000(shell)` 권한으로 동작한다. 소매용 삼성 펌웨어에서는
`adb root`가 거부된다:

```
adbd cannot run as root in production builds
```

| 영역 | 접근 |
|---|---|
| `/sdcard` 전체 (사진·영상·다운로드·문서) | **읽기·쓰기·삭제 가능** |
| 앱 설치/삭제 | **가능** |
| 스크린샷·화면 녹화·Logcat | **가능** |
| debug 빌드 앱의 내부 데이터 (`run-as`) | **가능** |
| 다른 앱의 내부 데이터 `/data` | 거부 |
| 보안 폴더 | 거부 |

### 보안 폴더는 안전한가 — 검증 결과

보안 폴더는 **별도의 안드로이드 사용자 계정**이다:

```
$ adb shell pm list users
UserInfo{0:소유자:4c13} running
UserInfo{150:Secure Folder:61010} running
```

shell 권한으로는 앱 목록 조회조차 거부된다:

```
$ adb shell pm list packages --user 150
Error: java.lang.SecurityException: Shell does not have permission to access user 150
```

- 폴더 숨김이 아니라 **OS 수준 계정 격리**
- 데이터는 별도 키로 암호화되며, Z 폴드 7은 **Knox Vault**(별도 보안 프로세서)에 키 보관
- `adb backup` 류에도 포함되지 않음
- 루팅/부트로더 언락을 시도하면 Knox e-fuse가 끊어져 **보안 폴더 데이터는 복구 불가**

**결론: ADB 연결로 보안 폴더 내용은 노출되지 않는다.**
다만 `/sdcard`의 개인 사진·영상은 완전히 열려 있다.

## 작업 종료 후 되돌리기

**순서가 중요하다.** 승인 취소 버튼이 개발자 옵션 안에 있으므로:

1. `개발자 옵션` → **`USB 디버깅 승인 취소`**
   (개발자 옵션을 꺼도 폰에 저장된 PC의 ADB 공개키는 남는다. 먼저 지워야 한다)
2. `개발자 옵션` **마스터 토글 끄기**
3. `설정` → `보안 및 개인 정보 보호` → **`자동 차단` 다시 켜기**

자동 차단은 USB 명령 차단 외에도 승인되지 않은 앱 설치 차단, 악성코드 검사를
포함하므로 개발자 옵션을 꺼도 켜두는 편이 좋다.

### 다시 연결이 필요해지면 (30초)

1. `설정` → `휴대전화 정보` → `소프트웨어 정보` → **빌드번호 7번 탭**
2. `개발자 옵션` → `USB 디버깅` 켜기
3. `자동 차단` → `USB 케이블로 ... 차단` 끄기

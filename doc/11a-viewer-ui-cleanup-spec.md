# 11a. 뷰어 화면 정리 기획서

미디어 뷰어의 **앱 바와 재생 컨트롤에서 뺄 것을 뺀다.** 사진과 영상이 화면을 다 쓰고,
남는 조작 요소만 그 위에 최소한으로 얹힌다.

이 문서는 *무엇을 만들 것인가*만 정의한다. 구현 방법·작업 순서는
[12번 계획서](12-video-viewer-plan.md)의 **10단계**에서 다룬다.

- 작성일: 2026-08-29
- 프로젝트: **PhotoExplorer** (`natae77/PhotoExplorer`, `zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 브랜치: `feature/media-view-mode` — 기준 커밋 `b35d0fba`
- 상태: **확정** — 남은 것은 실측 확인뿐(§7)

**개정 이력** — 11번과 같은 규칙을 쓴다. 개정할 때 새 문서를 만들지 않고 **본문을 직접 고친다.**

| 개정 | 날짜 | 무엇이 바뀌었나 |
|---|---|---|
| 1차 | 2026-08-29 | 최초 작성 |
| 2차 | 2026-08-29 | §6.1 — 동영상 스피너의 출처가 썸네일 로딩과 버퍼링 **두 곳**임을 확인하고, 둘을 하나로 합치는 것으로 고침 |
| 3차 | 2026-08-29 | 구현·에뮬레이터 검증 반영 — §7에 6번(상태바 글자 가독성) 추가 |
| 4차 | 2026-08-29 | 실기기(SM-F971N) 검증 반영 — §7의 6번은 에뮬레이터 한정으로 확인되어 닫음 |
| 5차 | 2026-08-29 | §6.1 — 슬라이더를 끄는 동안 스피너를 띄우지 않는 예외 추가 ([13번](13-viewer-performance.md)) |

> **11번과의 관계.** 이 문서는 [11번 동영상 뷰어 기획서](11-video-viewer-spec.md)의
> **후속 개정**이다. 11번이 정한 것 중 **§6.1(기본 컨트롤을 그대로 쓴다)과
> §6.3의 배속 표시 규칙**을 뒤집는다. 11번 본문의 해당 자리에는 "11a로 대체" 표시를 넣어 뒀다.
> 그 외 11번의 결정(D1~D12)은 전부 그대로 살아 있다.
>
> 별도 문서로 둔 이유는 **범위가 동영상만이 아니기 때문이다.** 앱 바 변경(§3)은
> 사진 페이지에도 똑같이 걸린다. 11번은 동영상 뷰어 문서라 여기에 담기에 맞지 않는다.
>
> **부록의 결정 번호는 11번을 이어 쓴다** — 11번이 D12에서 끝났으므로 여기는 D13부터다.

## 1. 배경

뷰어를 열고 화면을 한 번 탭하면 지금 이런 것들이 함께 뜬다.

```
┌──────────────────────────────┐
│ ← IMG_0421.MOV               │  ← 검정 50% 판, 상태바까지 덮음
│    3 / 20  1.5×          ⋮   │
├──────────────────────────────┤
│                              │
│          (사진 / 영상)        │
│                              │
├──────────────────────────────┤
│                              │  ← 검정 스크림, 220dp 높이
│      ⟲    ▶    ⟳        ⚙   │
│  0:03 ━━━●───────────  0:47  │
└──────────────────────────────┘
```

무엇이 어디서 오는지는 이렇다.

| 화면에 보이는 것 | 출처 |
|---|---|
| 위쪽 검정 판 | `appBarLayout`의 `?colorAppBarSurface` = `@color/dark_50_percent` ([themes.xml:89](../app/src/main/res/values/themes.xml#L89)) |
| 파일 이름 | 툴바 제목 ([MediaViewerFragment.kt:511](../app/src/main/java/me/zhanghai/android/files/viewer/media/MediaViewerFragment.kt#L511)) |
| `3 / 20`, `1.5×` | 툴바 부제목 ([MediaViewerFragment.kt:527](../app/src/main/java/me/zhanghai/android/files/viewer/media/MediaViewerFragment.kt#L527)) |
| 아래쪽 검정 판 | Media3 기본 컨트롤 레이아웃의 `exo_controls_background` + `minHeight="220dp"` ([media_viewer_fragment.xml:19](../app/src/main/res/layout/media_viewer_fragment.xml#L19)) |
| 톱니바퀴 `⚙` | Media3 기본 컨트롤의 `exo_settings` — 안에 **재생 속도**와 **오디오 트랙 선택**이 들어 있다 |
| 영상 넘길 때 도는 원 | 동영상 페이지의 `ProgressBar` + `show_buffering="when_playing"` ([media_viewer_video_item.xml:21](../app/src/main/res/layout/media_viewer_video_item.xml#L21)) |

**문제는 이것들이 실제로 쓰이지 않는다는 것이다.**

- 파일 이름과 `3 / 20`은 이 앱에서 **읽을 일이 없다.** 어떤 사진을 보고 있는지는 사진이 말해 준다.
- 톱니바퀴 안의 두 항목 중 **속도는 이미 `⋮` 메뉴에 따로 있고**([media_viewer.xml:13](../app/src/main/res/menu/media_viewer.xml#L13)),
  오디오 트랙은 폰으로 찍은 영상에 **하나뿐이라 고를 것이 없다.**
- 검정 판은 그 안 내용물이 몇 개 없는데도 화면의 위아래를 두껍게 잘라먹는다. 특히 하단은
  `220dp`가 고정으로 잡혀 있다.

넘길 때마다 화면 한가운데서 도는 원도 마찬가지다. 로컬 파일은 대부분 눈 깜빡할 사이에
준비되므로, 스피너는 **정보가 아니라 깜빡임**으로만 보인다.

## 2. 목표 / 비목표

**목표**

1. 상·하단을 통째로 덮는 **반투명 검정 판을 없앤다.** 사진과 영상이 화면 끝까지 쓴다.
2. 앱 바에서 **파일 이름·매수·배속 표시를 없앤다.**
3. 하단 컨트롤에서 **톱니바퀴를 없앤다.** 오디오는 항상 자동으로 고른다.
4. 판이 사라진 자리에서 아이콘과 시간이 계속 읽히도록, **요소마다 자기 몫의 스크림**을 준다.
5. 동영상 버퍼링 표시를 **지연 표시**로 바꿔 짧은 깜빡임을 없앤다.
6. 재생 슬라이더의 **터치 판정을 1.5배**로 넓힌다.

**비목표 (이번 범위 아님)**

- **이미지 로딩 스피너** — 그대로 둔다 (D18)
- **재생 속도 기능 자체** — `⋮` 메뉴에 그대로 남는다. 없어지는 것은 **표시**뿐이다 (D15)
- **컨트롤 버튼 구성 변경** — 10초 뒤/앞, 재생/일시정지는 그대로다 (§4.2)
- **아이콘 그래픽 교체, 테마 색 변경, 새 색 토큰 추가**
- **이미지 페이지에서 파일 이름을 볼 다른 수단 만들기** — §7의 미결 1번
- **몰입 모드 토글 방식, 아래로 스와이프 닫기** — 손대지 않는다

## 3. 상단 앱 바

### 3.1 배경을 없앤다

`appBarLayout`의 배경을 **완전 투명**으로 바꾼다.

이 배경은 상태바 영역까지 그리고 있었다 —
"Our app bar will draw the status bar background" ([MediaViewerFragment.kt:118](../app/src/main/java/me/zhanghai/android/files/viewer/media/MediaViewerFragment.kt#L118)).
`statusBarColor`는 이미 `TRANSPARENT`이므로, 앱 바 배경만 없애면 **상태바 자리까지 사진이 올라온다.**
이것이 의도한 결과다.

인셋 패딩(`applySystemWindowInsetsToPadding`)은 **그대로 둔다.** 아이콘이 상태바나
노치 아래로 들어가면 안 된다.

### 3.2 지우는 것

| 지금 | 뒤 |
|---|---|
| 툴바 제목 = 파일 이름 | **없음** |
| 툴바 부제목 = `3 / 20` | **없음** |
| 툴바 부제목 = `1.5×` (1× 아닐 때) | **없음** — 11번 §6.3의 표시 규칙을 폐기한다 (D15) |

제목·부제목을 갱신하던 로직은 통째로 없어진다. 배속을 바꿨을 때 화면에 남는 피드백은
**재생이 실제로 빨라지는 것**과 `⋮` → 재생 속도 메뉴의 라디오 표시뿐이다.

### 3.3 남는 것 — 요소별 스크림

앱 바에 남는 것은 **뒤로가기 화살표 `←`** 와 **오버플로 `⋮`** 둘뿐이다.
배경 판이 없어졌으므로 흰 하늘이나 밝은 벽 위에서는 흰 아이콘이 사라진다.
그래서 **아이콘마다 원형 반투명 디스크**를 뒤에 깐다.

| 항목 | 값 |
|---|---|
| 모양 | 원 |
| 색 | `@color/dark_50_percent` (`#80000000`) — 기존 토큰을 그대로 쓴다. 새 색을 만들지 않는다 |
| 지름 | **40dp** — 터치 타깃 48dp 안에 들어가고, 24dp 아이콘 둘레로 8dp 여백이 남는다 |
| 적용 대상 | 툴바 내비게이션 아이콘, 오버플로 아이콘 |

디스크는 **아이콘 드로어블 자체에 넣는다** (원 + 아이콘을 겹친 한 장). 툴바 내부 뷰를
런타임에 찾아 `background`를 꽂는 방식은 쓰지 않는다 — 그 뷰는 메뉴가 갱신될 때마다
다시 만들어지므로 깨지기 쉽다.

## 4. 하단 재생 컨트롤

### 4.1 배경 판을 없앤다

Media3 기본 컨트롤 레이아웃에는 스크림 뷰와 톱니바퀴가 **레이아웃에 박혀 있어** XML 속성으로
뗄 수 없다. 그래서 **컨트롤 레이아웃을 우리 것으로 바꾼다** (D17).

`minHeight="220dp"`도 함께 없앤다. 이 값은 기본 레이아웃이 "minimal mode"로 내려가
시간 표시와 10초 버튼을 감추는 것을 막으려고 넣은 것인데([12번 §1](12-video-viewer-plan.md)의
"달라진 곳" 2번), 우리 레이아웃에는 minimal mode 자체가 없으므로 필요가 없다.
컨트롤은 **자기 내용물만큼만** 높이를 차지한다.

인셋 패딩은 그대로 둔다 — 제스처 바 위로 올라와야 한다.

### 4.2 무엇을 남기고 무엇을 빼나

| 남긴다 | 비고 |
|---|---|
| 10초 뒤로 `⟲` | 원형 스크림 |
| 재생 / 일시정지 | 원형 스크림 |
| 10초 앞으로 `⟳` | 원형 스크림 |
| 현재 위치 `0:03` | 라운드 사각 칩 |
| 재생 슬라이더 | §5 |
| 전체 길이 `0:47` | 라운드 사각 칩 |

| 뺀다 | 이유 |
|---|---|
| **톱니바퀴 `⚙`** | 속도는 `⋮`에 있고, 오디오 트랙은 고를 것이 없다 (D16) |
| 이전 / 다음 | 지금도 꺼져 있다 |
| 셔플 · 반복 · 자막 · VR · 전체화면 | 지금도 꺼져 있거나 안 쓴다. 새 레이아웃에는 아예 넣지 않는다 |

스크림 규격은 §3.3과 같다. 시간 텍스트만 모양이 다르다.

| 항목 | 값 |
|---|---|
| 모양 | 라운드 사각 |
| 색 | `@color/dark_50_percent` |
| 모서리 반지름 | 4dp |
| 안쪽 여백 | 좌우 6dp, 위아래 2dp |

### 4.3 오디오는 항상 자동

톱니바퀴가 사라지면 사용자가 트랙을 고를 창구가 없어진다. **별도로 할 일은 없다** —
ExoPlayer의 기본 트랙 선택이 그대로 동작한다. 폰으로 찍은 영상은 오디오 트랙이 하나뿐이라
결과도 지금과 같다.

11번 §5.5(오디오 포커스)와 §2 비목표의 "음소거 토글 없음"은 **그대로 유효하다.**

## 5. 재생 슬라이더 — 터치 판정 1.5배

지금 슬라이더는 손가락으로 잡기 어렵다. **잡을 수 있는 세로 범위를 1.5배로 넓힌다.**

| 항목 | 지금 | 뒤 |
|---|---|---|
| 터치 판정 높이 | 26dp (Media3 기본값) | **39dp** |
| 막대 두께 | 기본값 | **그대로** |
| 동그라미(스크러버) 크기 | 기본값 | **그대로** |

**보이는 모습은 바뀌지 않는다.** 커지는 것은 손가락이 닿는 범위뿐이다.
슬라이더 뷰가 세로로 커지므로, 위아래 여백은 지금과 비슷하게 보이도록 다시 잡는다.

드래그 중 화면이 따라 움직이는 동작(스크러빙)은 지금 그대로 유지한다.

## 6. 로딩 표시

### 6.1 동영상 — 표시를 하나로 합치고, 0.5초 넘게 기다릴 때만 보여준다

**지금 동영상 페이지에서 도는 원은 출처가 두 곳이다.** 하나만 손보면 나머지가 그대로 깜빡인다.

| 출처 | 언제 뜨나 |
|---|---|
| 페이지 자신의 `ProgressBar` — **썸네일 로딩용** | 페이지가 바인딩되는 즉시 ([MediaViewerAdapter.kt:130](../app/src/main/java/me/zhanghai/android/files/viewer/media/MediaViewerAdapter.kt#L130)) |
| 재생 뷰가 스스로 그리는 **버퍼링 표시** (`show_buffering`) | 재생을 준비하는 동안 |

**둘을 페이지마다 하나의 표시로 합치고, 그 하나를 지연시킨다.** 재생 뷰의 자체 표시는 끈다 —
주체가 둘이면 "둘 다 뜨거나, 하나만 남는" 상태가 생긴다.

합친 표시는 **기다림이 0.5초 이상 이어질 때만** 뜬다. 그 전에 끝나면 아예 뜨지 않는다.

| 상태 | 동작 |
|---|---|
| 썸네일 로딩 시작 **또는** 버퍼링 시작 | 0.5초 뒤에 띄우도록 예약만 한다 |
| 0.5초 안에 둘 다 끝남 | 예약을 취소한다. **아무것도 안 보인다** |
| 0.5초 넘게 이어짐 | 스피너를 띄운다 |
| 둘 다 끝남 / 오류 / 페이지 이탈 | 예약을 취소하고 스피너를 숨긴다 |

**둘 중 하나라도 진행 중이면 켜져 있고, 둘 다 끝나야 꺼진다.** 썸네일이 먼저 끝났다고
버퍼링 중에 스피너가 사라지면 안 된다.

**예외 — 슬라이더를 끄는 동안에는 띄우지 않는다.** 손가락이 슬라이더에 있으면 플레이어는
계속 버퍼링 상태이므로 0.5초를 금방 넘긴다. 그런데 탐색 중에는 **그림을 봐야 하므로**
가운데 스피너가 가려서는 안 된다. 스크럽이 시작되면 이미 예약된 표시도 취소한다.
자세한 것은 [13번 §5](13-viewer-performance.md) 참고.

**오류 표시는 지금 그대로다.** 재생에 실패하면 11번 §8대로 안내 문구와 "다른 앱으로 열기"가 뜬다.

### 6.2 이미지 — 손대지 않는다

사진 페이지의 로딩 스피너는 **그대로 둔다** (D18). 큰 원본이나 SAF 경로에서는 실제로
기다리는 시간이 있고, 그때 아무 표시가 없으면 멈춘 것처럼 보인다.

| 1 | **이미지의 파일 이름을 볼 수단이 없어진다** | 동영상은 `⋮` → 세부 정보에 이름이 있지만, 사진은 뷰어 안에서 이름을 볼 방법이 아예 사라진다. 실제로 불편한지 써 보고, 필요하면 사진에도 세부 정보 항목을 두는 것을 **별건으로** 정한다 |
| 2 | 밝은 장면에서 아이콘·시간이 읽히는가 | 40dp 디스크와 검정 50%가 충분한지. 부족하면 색을 `dark_70_percent`로 올린다 |
| 3 | 컨트롤 레이아웃을 갈아끼운 뒤에도 시간 표시와 10초 버튼이 남는가 | 12번 §1 "달라진 곳" 2번에서 한 번 당한 곳이다. minimal mode가 우리 레이아웃에서도 끼어드는지 확인한다 |
| 4 | 슬라이더 판정을 넓혀도 좌우 페이지 넘김과 안 싸우는가 | 슬라이더가 세로로 커지면 그만큼 `ViewPager2`의 스와이프를 가져간다 |
| 5 | 0.5초가 적당한가 | 실기기 로컬 파일에서 스피너가 거의 안 뜨는지, 큰 4K 파일에서는 제때 뜨는지 |
| 6 | ~~**상태바의 시계·아이콘이 밝은 사진 위에서 안 읽힌다**~~ **— 실기기에서는 문제 없음** | 2026-08-29 에뮬레이터에서 확인했다. 앱 바 배경이 상태바 자리까지 어둡게 깔아 주던 것이 없어지면서, **흰색인 시스템 상태바 글자가 밝은 사진 위에서 흐려진다.** 앱 바를 내리면(몰입 모드) 상태바도 같이 사라지므로 **앱 바가 떠 있는 동안에만** 생긴다. **그런데 같은 날 SM-F971N에서는 재현되지 않았다** — One UI가 상태바 아이콘 색을 배경에 맞춰 바꿔서, 밝은 곳에서는 검은 글자로 나온다. **AOSP 에뮬레이터 쪽 동작으로 보이므로 손대지 않는다.** 다른 기기에서 다시 보이면 그때 판단한다 |

## 8. 수용 기준

1. 뷰어를 열고 탭했을 때 **화면 위아래에 반투명 검정 판이 보이지 않는다.**
2. 상태바 영역까지 사진/영상이 올라온다. 아이콘은 상태바를 침범하지 않는다.
3. 앱 바에 **파일 이름·`3 / 20`·`1.5×` 가 어디에도 없다.**
4. 뒤로가기와 `⋮` 는 **원형 반투명 디스크 위에** 있고, 흰 사진 위에서도 보인다.
5. 하단 컨트롤에 **톱니바퀴가 없다.**
6. 하단 컨트롤에 10초 뒤로 · 재생/일시정지 · 10초 앞으로 · 현재 위치 · 슬라이더 · 전체 길이가
   **모두 남아 있다.**
7. 시간 표시는 라운드 사각 칩 위에 있다.
8. `⋮` → 재생 속도가 그대로 동작하고, 고른 값에 라디오 표시가 붙는다.
9. 슬라이더를 지금보다 **눈에 띄게 잡기 쉽다.** 동그라미 크기는 그대로다.
10. 슬라이더를 잡고 끄는 동안 화면이 따라 움직인다.
11. 로컬 동영상 페이지로 넘어갈 때 **가운데 스피너가 뜨지 않는다.** 썸네일 로딩과 버퍼링 어느 쪽으로도 뜨지 않는다.
12. 재생할 수 없는 동영상에서는 지금처럼 안내 문구와 "다른 앱으로 열기"가 뜬다.
13. 사진 페이지의 로딩 스피너는 지금과 같다.
14. 탭으로 앱 바와 컨트롤이 같이 나타나고 같이 사라진다 (11번 §6.2 유지).
15. 아래로 스와이프해 닫기, 좌우 넘김, 확대, 삭제·공유가 모두 그대로다.

## 부록. 확정된 결정 기록

번호는 [11번 부록](11-video-viewer-spec.md)의 D12를 이어 쓴다.

| # | 질문 | 결정 |
|---|---|---|
| D13 | 상·하단 스크림을 어떻게 없앨 것인가 | **판 전체를 없애고 요소마다 스크림을 준다.** 완전 투명은 밝은 장면에서 아이콘이 사라지고, 그라데이션은 결국 "얇은 판"이라 없앤 이유가 반쯤 남는다. 아이콘은 원, 텍스트는 라운드 사각 — 조작 요소가 있는 자리만 정확히 어두워진다 |
| D14 | 파일 이름과 매수를 남길 것인가 | **없앤다.** 어떤 사진을 보고 있는지는 사진이 말해 준다. 파일 이름이 필요한 경우는 파일 목록에서 이미 해결된다. 대가로 사진의 이름을 뷰어에서 볼 수 없게 되는데, 실제로 불편한지 써 보고 별건으로 정한다 (§7의 1번) |
| D15 | 배속 표시(`1.5×`)를 어디로 옮길 것인가 | **옮기지 않고 없앤다.** 부제목을 없애는 김에 하단으로 옮기면 없애려던 요소가 자리만 바꿔 돌아온다. 배속은 재생 속도로 바로 느껴지고, `⋮` 메뉴를 열면 라디오 표시로 확인된다. 11번 §6.3의 "부제목에 표시" 규칙을 폐기한다 |
| D16 | 톱니바퀴를 없애면 오디오 트랙은 어떻게 되나 | **항상 자동.** ExoPlayer 기본 트랙 선택에 맡긴다. 폰으로 찍은 영상은 오디오가 하나뿐이라 고를 것이 없고, 고를 수 있게 두면 쓰지 않는 메뉴 하나를 화면에 남기게 된다 |
| D17 | Media3 기본 컨트롤 레이아웃을 계속 쓸 것인가 | **우리 레이아웃으로 바꾼다.** 11번 D6은 "기본 컨트롤을 쓰고 색만 맞춘다"였는데, 스크림과 톱니바퀴가 레이아웃에 박혀 있어 속성으로는 못 뗀다. 다만 **컨트롤의 동작 로직은 그대로 Media3 것을 쓴다** — 레이아웃만 갈아끼우는 것이라 D6이 피하려던 "슬라이더·시간 갱신을 직접 구현"은 여전히 안 한다 |
| D18 | 이미지 로딩 스피너도 없앨 것인가 | **그대로 둔다.** 요청은 동영상 쪽이었고, 큰 원본·SAF 경로에서는 실제로 기다리는 시간이 있다. 거기서 표시가 없으면 앱이 멈춘 것처럼 보인다 |
| D19 | 동영상 스피너를 아예 없앨 것인가 | **둘을 하나로 합치고 0.5초 지연 표시로 한다.** 표시가 썸네일 로딩용과 버퍼링용 둘로 나뉘어 있어, 하나만 지연시키면 다른 하나가 그대로 깜빡인다. 아예 없애면 아예 없애면 네트워크나 큰 파일에서 멈춘 것과 구별이 안 된다. 로컬 파일은 대부분 0.5초 안에 시작하므로 실사용에서는 안 보이는 것과 같다 |
| D20 | 슬라이더를 어떻게 키울 것인가 | **터치 판정 높이만 26dp → 39dp.** 동그라미와 막대를 같이 키우면 화면이 무거워진다. 잡기 어려운 것이 문제였지 작아 보이는 것이 문제가 아니었다 |

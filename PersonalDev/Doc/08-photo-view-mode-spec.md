# 08. 미디어(Media) 보기 모드 기획서

파일 목록의 보기 모드를 **목록(List) / 바둑판(Grid)** 2종에서
**목록 / 바둑판 / 미디어(Media)** 3종으로 확장한다.

이 문서는 *무엇을 만들 것인가*만 정의한다. 구현 방법·작업 순서는 별도 계획서에서 다룬다.

- 작성일: 2026-08-25 (4차 개정 — D1~D14 전부 확정, `.nomedia` 제약 반영)
- 프로젝트: **PhotoExplorer** (`zhanghai/MaterialFiles` fork)
- 대상 버전: 1.7.4 (versionCode 39) 기준 소스
- 상태: **확정** — 남은 것은 실측 확인뿐(§11)

> **이름 정리**: 처음에는 "Photo 모드"로 불렀으나 동영상도 포함하므로,
> 사용자에게 보이는 라벨과 내부 이름 모두 **미디어 / `MEDIA`** 로 통일한다.

## 1. 배경

현재 보기 모드는 두 가지다.

| 모드 | 레이아웃 | 항목 구성 |
|---|---|---|
| 목록 | 1열 | 아이콘 + 이름 + (수정시각·크기) + `⋮` |
| 바둑판 | 화면폭/180dp 열 (최소 2) | 16:9 썸네일 + 아이콘 + 이름 + `⋮` |

근거: [FileListFragment.kt:656](../../app/src/main/java/me/zhanghai/android/files/filelist/FileListFragment.kt#L656) `updateSpanCount()`,
[file_item_grid.xml](../../app/src/main/res/layout/file_item_grid.xml)

바둑판 모드는 썸네일이 16:9인 데다 항목마다 이름 줄과 여백이 붙어서, 사진·동영상이 수십~수백 개
들어있는 폴더를 **훑어보기**에는 밀도가 낮다. 그리고 정렬 기준에 **촬영 시각**이 없어서
"최근에 찍은 것부터 보기"가 안 된다 — 수정 시각은 파일을 옮기는 과정에서 갱신될 수 있어
촬영 순서와 어긋난다 ([06번 문서](06-video-date-metadata.md)).

## 2. 목표 / 비목표

**목표**

1. 사진·동영상을 격자로 빽빽하게 보여주는 세 번째 보기 모드를 추가한다.
2. 그 모드에서는 **미디어 생성 시각(촬영 시각)** 으로 정렬하고, 진입하면 **가장 최근 미디어가 보이는 위치**에서 시작한다.
3. 보기 모드를 **폴더별로** 기억한다. "이 폴더에만 적용" 체크박스는 없앤다.
4. 기존 파일 작업(열기·복사·삭제·이름변경·공유·속성 등)은 항목별 `⋮` 메뉴로 그대로 쓸 수 있다.

**비목표 (이번 범위 아님)**

- 날짜별 그룹 헤더("오늘", "지난 주") 등 갤러리식 섹션 구분.
- 사진 뷰어/편집기 개선, 슬라이드쇼, 즐겨찾기.
- 하위 폴더까지 재귀적으로 긁어 모으는 "미디어 모아보기".
- 핀치 줌으로 열 수 조절.
- 동영상 재생 시간(길이) 배지.

## 3. 미디어 모드 — 표시 대상

| 대상 | 표시 | 형태 |
|---|---|---|
| 이미지 파일 | O | 정사각형 썸네일 타일 |
| 동영상 파일 | O | 정사각형 썸네일 타일 + ▶ 표시 |
| **폴더** | **O** | 정사각형 타일(폴더 아이콘 + 이름 1줄) — 어두운 배경으로 미디어 타일과 구분 |
| 그 외 파일(문서·압축·오디오 등) | X | 표시하지 않음 |

- 판정 기준은 기존 MIME 유틸을 그대로 쓴다: `MimeType.isImage`, `MimeType.isVideo`
  ([MimeTypeTypeExtensions.kt:43](../../app/src/main/java/me/zhanghai/android/files/file/MimeTypeTypeExtensions.kt#L43))
- **폴더를 표시하는 이유**: 폴더를 숨기면 미디어 모드에서 하위 폴더로 들어갈 방법이 없어져
  파일 관리자로서 쓸 수 없게 된다. "이름을 안 보여준다"는 원칙은 **미디어 타일에만** 적용하고,
  폴더 타일에는 이름을 1줄로 표시한다.
- 숨김 파일 표시 설정(`FILE_LIST_SHOW_HIDDEN_FILES`)은 기존 규칙을 그대로 따른다.
- **툴바 부제(개수)**: 기존 그대로 **폴더/파일 전체 개수**를 표시한다. 미디어 모드에서 화면에
  안 보이는 파일도 개수에는 포함된다(사용자가 "파일이 사라졌다"고 오해하지 않도록).

## 4. 미디어 모드 — 레이아웃

| 항목 | 값 |
|---|---|
| 타일 형태 | 정사각형 (1:1) |
| 썸네일 스케일 | `centerCrop` (잘라서 꽉 채움, 여백 없음) |
| 타일 간격 | **0** — 바둑판처럼 맞닿음. 좌우 화면 가장자리 여백도 0 |
| 모서리 | 각지게(라운드 없음). 바둑판 모드의 Material3 라운드 배경은 적용하지 않음 |
| 열 수 | 화면 폭에 따라 가변, **최소 4열** |
| 파일 이름 | 미디어 타일: 표시 안 함 / 폴더 타일: 1줄 표시 |
| 수정시각·크기 | 표시하지 않음 |

**열 수 산식(제안)**: `max(4, 사용가능폭dp / 90)`
바둑판의 기존 산식(`폭/180`, 최소 2)과 같은 형태로 기준 폭만 절반으로 줄인 것이다.
좌측 영구 드로어가 열려 있으면 그 폭을 빼는 기존 처리도 동일하게 적용한다.

| 기기/상태 | 사용 폭 | 열 수 |
|---|---|---|
| Pixel 8 세로 | 411dp | 4 |
| Pixel 8 가로 | 914dp | 10 |
| Fold 7 펼침 세로 | ~674dp | 7 |
| 태블릿 + 드로어 열림 | 1280−320=960dp | 10 |

### 4.1 타일 구성

```
미디어 타일                    폴더 타일
┌─────────────┐              ┌─────────────┐
│           ⋮ │              │           ⋮ │
│             │              │     [폴더]   │
│   썸네일     │              │             │
│             │              │ 폴더이름…    │
│ ▶           │              │             │
└─────────────┘              └─────────────┘
```

- **`⋮` 메뉴 버튼**: 우상단 오버레이, **항상 표시**. 어두운 사진 위에서도 보이도록
  반투명 스크림 또는 그라데이션을 옅게 깐다. 누르면 기존 `file_item` 메뉴를 그대로 띄운다.
- **동영상 구분**: 좌하단에 작은 ▶ 아이콘. **재생 시간은 표시하지 않는다**.
- **썸네일 로딩 실패/미지원**: 파일 종류 아이콘을 타일 중앙에 놓고 배경은 단색으로 채운다.
- **배지**(심볼릭 링크·암호화 등): 미디어 모드에서는 생략한다. 정보는 `⋮` → 속성에서 확인.

### 4.2 인터랙션

| 동작 | 결과 |
|---|---|
| 미디어 타일 탭 | 파일 열기 |
| 폴더 타일 탭 | 폴더 열기(이동) |
| 롱프레스 | 선택 모드 진입 + 해당 항목 선택 |
| 선택 모드에서 탭 | 선택 토글 |
| `⋮` 탭 | 항목 메뉴 |
| 선택됨 표시 | 타일 위 반투명 오버레이 + 체크 마크. 선택 모드에서는 `⋮`를 체크 마크로 교체 |

> 목록/바둑판 모드는 "아이콘 영역 탭 = 선택"이지만 미디어 타일에는 별도 아이콘 영역이 없으므로,
> **롱프레스 진입 방식**만 제공한다.

## 5. 미디어 생성 시각 — 어디서 읽는가 (실측 근거 포함)

### 5.1 "파일 생성 날짜"를 쓸 수 있는가 → **쓸 수 없다**

가장 싼 방법은 파일시스템의 생성 시각(btime)을 쓰는 것이다. 실제로 확인한 결과 **세 겹으로 막힌다.**

**(1) 앱 코드에 이미 가짜로 채워져 있다**

```kotlin
// provider/linux/LinuxFileAttributes.kt:47
val creationTime = lastModifiedTime      // ← 생성 시각 = 수정 시각
```

`ContentProviderFileAttributes`도 `creationTime() = lastModifiedTime()`이다.
즉 이 앱에서 `creationTime()`을 읽으면 **그냥 mtime이 돌아온다.**
(진짜 생성 시각이 들어가는 건 압축 파일 안의 항목뿐 — `ReadArchive`의 `birthtime`.)

**(2) 안드로이드가 값을 안 준다**

Pixel 8 에뮬레이터(Android 16)에서 확인:

```
$ stat -c '%n birth=%W mtime=%Y' /sdcard/SwingTestData/IMG_6429.mov
/sdcard/SwingTestData/IMG_6429.mov birth=? mtime=1775872400
```

`birth=?` — 값이 없다. `/sdcard`는 FUSE 계층이라 btime을 노출하지 않는다.
(참고로 같은 파일을 PC에서 `stat` 하면 `Birth:` 줄이 나온다. NTFS는 준다.)

**(3) 설령 얻더라도 의미가 없다**

btime은 "이 파일시스템에 만들어진 시각"이다. 사진을 폰→PC→에뮬레이터로 옮기면
btime은 **복사한 시각**이 되어 전부 오늘 날짜로 뭉친다. 촬영 순서와 무관하다.
→ mtime보다도 나쁘다(mtime은 복사 도구에 따라 보존되기도 한다).

**결론: 촬영 시각은 파일 내용(EXIF / MP4 메타데이터)에서만 얻을 수 있다.**

### 5.2 MediaStore는 쓸 수 없다 (`.nomedia`)

안드로이드 미디어 스캐너가 이미 읽어 둔 값(`MediaStore.datetaken`)을 쿼리 한 번으로 가져오면
가장 싸다. 실제로 정확도도 확인했다 — 에뮬레이터 실측:

```
20260819_062806_1.mp4  datetaken=1787088588000  → 2026-08-18 21:29:48 UTC
```

원본 파일의 MP4 `mvhd creation_time`을 직접 파싱한 값과 **초 단위까지 일치**한다
([06번 문서](06-video-date-metadata.md)의 검증값과 동일).

**그러나 이 경로는 쓸 수 없다.**

사진을 모아두는 주요 폴더에는 **`.nomedia` 파일을 넣어 갤러리 앱에서 감출 것**이기 때문이다.
`.nomedia`가 있는 폴더의 파일은 미디어 스캐너가 건너뛰므로 `MediaStore`에 **행 자체가 없다.**
즉 정작 미디어 모드를 가장 많이 쓸 폴더에서 아무 값도 못 얻는다.

에뮬레이터에서 확인 (`/sdcard/SwingTestData`, 동영상 20개):

| 상태 | MediaStore 행 수 |
|---|---|
| `.nomedia` 없음 | **20** |
| `.nomedia` 넣고 재스캔 | **0** (`No result found.`) |

> 부분적으로만 쓰는 것(있으면 쓰고 없으면 직접 읽기)도 가능하지만,
> **주 사용처에서 항상 실패하는 경로**를 위해 두 갈래 코드를 유지할 이유가 없다.
> 게다가 `.nomedia` 유무에 따라 정렬 속도가 폴더마다 들쭉날쭉해져 동작을 예측하기 어려워진다.
> → **MediaStore는 쓰지 않는다.** 파일에서 직접 읽는 경로 하나로 간다(§5.5).

### 5.3 ⚠️ 그런데 메타데이터가 항상 옳지는 않다 (실측)

`D:\Work\SwingTestData` 50개로 확인한 결과, **두 값이 서로 반대 방향으로 틀린다.**

| 파일 | 촬영 메타데이터(mvhd) | 수정 시각(mtime) | 실제로 맞는 쪽 |
|---|---|---|---|
| `20260819_062806_1.mp4` | 2026-08-18 21:29 | 2026-08-22 00:36 | **메타데이터** (mtime은 PC 복사 시각) |
| `IMG_6429.mov` | 2026-08-18 05:46 | 2026-04-11 01:53 | **mtime** (메타데이터가 전송 시각으로 덮임) |
| `IMG_6457.mov` | 2026-08-18 05:46 | 2026-04-18 00:46 | **mtime** |
| `IMG_6458.mov` | 2026-08-18 05:46 | 2026-04-18 00:56 | **mtime** |

`.mov` 48개는 mvhd가 **전부 2026-08-18 05:46:00±1초** — 폰에서 PC로 옮길 때 메타데이터가
전송 시각으로 다시 쓰인 것이다. 반대로 `.mp4` 2개는 mtime이 복사 시각으로 갱신됐다.

**→ 어느 한쪽만 믿으면 절반이 틀린다.**

### 5.4 채택 규칙: 둘 중 **이른 쪽**을 쓴다

```
미디어 생성 시각 = min(촬영 메타데이터, 파일 수정 시각)
```

근거: **촬영은 파일이 마지막으로 쓰인 시점보다 나중일 수 없다.** 두 값 중 늦은 쪽은
"옮기는 과정에서 덧씌워진 시각"일 가능성이 크므로 버린다.

위 실측 데이터에 적용하면:

| 파일 | min() 결과 | 판정 |
|---|---|---|
| `20260819_062806_1.mp4` | 2026-08-18 21:29 (메타데이터) | O |
| `IMG_6429.mov` | 2026-04-11 01:53 (mtime) | O |

**50개 전부 올바른 쪽이 선택된다.** 일반적인 경우(폰에서 바로 찍은 사진)는 두 값이 거의
같으므로 어느 쪽을 골라도 결과가 같다.

### 5.5 값 취득 순서 (파일 직접 읽기)

한 파일의 미디어 생성 시각을 구하는 절차:

1. **캐시 조회** — 키는 `경로 + 크기 + mtime`. 있으면 즉시 반환하고 끝.
2. **이미지** — `ExifInterface`로 `DateTimeOriginal`
   ([`inferDateTimeOriginal()`](../../app/src/main/java/me/zhanghai/android/files/fileproperties/image/ExifInterfaceExtensions.kt#L31)).
   EXIF는 파일 앞부분만 읽으므로 저렴하다.
3. **동영상** — **경량 파싱 우선**: 박스 체인을 따라가 `moov` → `mvhd`의 `creation_time`만 읽는다.
   파일 앞 16바이트로 첫 박스 크기를 얻고, 그 크기만큼 건너뛰어 다음 박스 헤더를 읽는 식으로
   `moov`에 도달한다. **파일 크기와 무관하게 읽는 양이 일정하다.**
   - 파싱 실패(비표준 컨테이너, mkv/webm 등) 시에만 `MediaMetadataRetriever`로 폴백한다.
     이쪽은 추출기 전체를 초기화하므로 훨씬 무겁다 — **폴백으로만** 쓴다.
   - ⚠️ "파일 뒤쪽 N바이트를 읽어 `moov`를 찾는" 방식은 쓰지 않는다.
     실측상 `moov`까지의 거리가 13KB~287KB로 편차가 커서, 고정 크기로 자르면 일부가 빗나간다(§5.7).
4. 그래도 못 얻으면 → mtime
5. §5.4의 `min(구한 값, mtime)` 적용
6. 결과를 캐시에 기록. **캐시는 앱을 껐다 켜도 유지**되어야 한다(첫 방문만 비용을 치른다).

**언제 읽는가 — 1차 로딩에 포함한다**

폴더 목록을 읽는 그 시점에 **같이 읽는다.** 목록을 띄운 뒤에 따로 읽는 방식은 쓰지 않는다.

```
FileListLiveData.loadValue()          ← 백그라운드 스레드
  └ 파일마다 loadFileItem()
      ├ readAttributes()   (기존)
      ├ MIME 판정          (기존)
      └ 미디어 생성 시각    ← 여기에 추가
```

- 목록이 화면에 나올 때 **이미 올바른 순서**다. mtime으로 임시 표시했다가 재정렬하는 단계가 없다.
- 로딩 중 화면은 기존과 동일하다 — 처음 여는 폴더는 진행 표시, 새로고침은 기존 목록 유지(§부록 참고).
  UI 스레드는 막히지 않는다.
- 스크롤 위치도 한 번만 정하면 된다(§6).

> 이 결정은 §5.7 실측(파일당 약 300바이트)에 근거한다.
> **실기기에서 눈에 띄게 느리면 목록을 먼저 띄우는 방식으로 바꾸는 걸 다시 검토한다**(§11).

**어떤 파일에 대해 읽는가**

- **이미지·동영상 파일만** 읽는다. 문서·압축 파일 등은 시도하지 않으므로,
  미디어가 없는 폴더(다운로드·문서 폴더 등)는 **추가 비용이 0**이다.
- 보기 모드나 정렬 기준과 무관하게 항상 읽는다. 목록 모드에서도 "미디어 생성 시각" 정렬이
  곧바로 동작한다.
- **원격 경로(SMB/SFTP 등)** 는 "썸네일용 원격 파일 읽기" 설정이 꺼져 있으면 읽지 않는다(mtime 사용).
  켜져 있어도 원격은 지연이 크므로 1차 로딩을 늘린다 — 계획서에서 별도 판단한다.
- **압축 파일 내부**는 읽지 않는다(mtime 사용).

**캐시가 특히 중요해진다**

`PathObserver`가 폴더 변경을 감지할 때마다 `loadValue()`가 다시 돈다
([FileListLiveData.kt](../../app/src/main/java/me/zhanghai/android/files/filelist/FileListLiveData.kt)).
캐시가 없으면 파일 하나 바뀔 때마다 폴더 전체 메타데이터를 다시 읽는다.
`경로 + 크기 + mtime` 키 캐시로 두 번째 이후는 조회만 하고 끝낸다.

### 5.7 경량 파싱 실측 (`D:\Work\SwingTestData` 50개)

**박스 구조** — 50개 전부 `moov`가 **파일 뒤쪽**에 있다.

| 박스 체인 | 파일 수 |
|---|---|
| `ftyp → mdat → moov` | 2 (`.mp4`) |
| `ftyp → wide → mdat → moov` | 48 (`.mov`) |

**읽는 양** — 체인을 따라가면 박스 헤더 16바이트씩 **3~4회**면 `moov`에 도달한다.

| 항목 | 값 |
|---|---|
| 박스 헤더 읽기 | 48~64 바이트 |
| `moov` 헤더에서 `mvhd` 찾기 | ~256 바이트 |
| **파일당 합계** | **약 300 바이트** |
| `mvhd` 파싱 성공률 | **50/50** |

**고정 크기 꼬리 읽기는 부적절** — 파일 끝에서 `moov`까지의 거리가 **13,804 ~ 287,309 바이트**로
편차가 크다. 뒤 256KB만 읽는 방식이면 **49/50**만 성공한다(1개는 287KB 지점).
체인을 따라가면 추측할 필요가 없다.

**기기 I/O 비용** — Pixel 8 에뮬레이터에서 파일 20개 대상 측정:

| 측정 | 파일당 |
|---|---|
| `dd` 프로세스 생성 오버헤드(1바이트 읽기) | 4.6 ms |
| 앞 64KB + 뒤 256KB 읽기 (`dd` 3회 spawn 포함) | 9~13 ms |

즉 측정값이 **프로세스 생성 비용에 묻힌다** — 실제 읽기 자체는 그보다 훨씬 작다.
앱 안에서는 프로세스 생성 없이 열기·시크·읽기만 하므로 파일당 1ms 미만으로 예상된다.

> ⚠️ 에뮬레이터는 호스트 SSD + 페이지 캐시 위에서 돈다. **실기기(UFS) 확인이 남아 있다**(§11).

### 5.6 정렬 규칙 세부

- 정렬 기준 `By.MEDIA_CREATED`를 새로 추가한다.
- **폴더 우선(directories first)** 옵션은 기존대로 존중한다. 폴더끼리는 이름순.
- 값이 같으면 기존처럼 이름순으로 안정 정렬한다.
- 이 기준은 **모든 보기 모드의 정렬 메뉴에 노출**한다. 미디어가 아닌 파일은 mtime으로 폴백되므로
  목록이 깨지지 않는다.

## 6. 미디어 모드 — 최신 항목부터 보기

- **기본 정렬**: `미디어 생성 시각` + **오름차순**(오래된 것 위 → 최신 아래).
- 미디어 모드로 폴더를 열면 **목록 맨 아래**(= 가장 최근 미디어)로 스크롤한 상태에서 시작한다.
  채팅 앱처럼 "아래가 최신"인 감각.
- 사용자가 내림차순으로 바꾸면 최신이 맨 위이므로 맨 위에서 시작한다.
- **예외 — 뒤로가기 복귀**: 하위 폴더에 들어갔다 나온 경우에는 기존 스크롤 위치 복원이 우선한다
  (`pendingState`, [FileListFragment.kt:619](../../app/src/main/java/me/zhanghai/android/files/filelist/FileListFragment.kt#L619)).
- **재정렬로 인한 스크롤 튐은 없다.** 생성 시각을 1차 로딩에서 함께 읽으므로(§5.5),
  목록이 처음 그려질 때 이미 정렬이 끝나 있다. 스크롤 위치는 그때 한 번만 정한다.

## 7. 폴더별 보기 모드 — "이 폴더에만 적용" 체크박스 제거

### 7.1 현재 동작과 문제

정렬 메뉴 맨 아래에 **"이 폴더에만 적용"**(Only for this folder,
[strings.xml:297](../../app/src/main/res/values/strings.xml#L297)) 체크박스가 있고,
켜야만 그 폴더의 보기 모드·정렬이 경로별로 저장된다
([FileViewSortPathSpecificLiveData.kt](../../app/src/main/java/me/zhanghai/android/files/filelist/FileViewSortPathSpecificLiveData.kt)).

| # | 문제 |
|---|---|
| L1 | 정렬 메뉴 맨 아래 체크 항목이라 있는 줄 모르고 지나친다 |
| L2 | **순서를 지켜야 한다** — 체크를 먼저 켠 *다음* 보기 모드를 바꿔야 폴더별로 남는다. 모르고 바꾸면 전역 설정이 바뀌어 모든 폴더가 따라 바뀐다 |
| L3 | 보기 모드와 정렬이 묶여 있어 따로 못 정한다 |

### 7.2 새 동작

**체크박스를 없애고, 보기 모드는 항상 폴더별로 기억한다.**

| 상황 | 동작 |
|---|---|
| 폴더에서 보기 모드를 바꿈 | **그 폴더에만** 저장한다 |
| 보기 모드를 한 번도 안 바꾼 폴더 | 전역 기본값으로 표시한다 |
| 그 폴더를 다시 방문 | 마지막에 지정한 모드로 열린다 |

- 사용자는 "이 설정이 어디에 적용되는가"를 더 이상 생각하지 않는다. 폴더마다 원하는 대로 바꾸면 된다.
- 전역 기본값은 **설정 화면에서만** 바꾼다(보기 모드를 바꿀 때마다 전역이 따라 바뀌면,
  사진 폴더를 미디어로 본 뒤 문서 폴더까지 미디어가 되어 버린다).
- 저장은 **명시적으로 바꾼 폴더만** 한다. 방문만 한 폴더는 아무것도 쓰지 않는다
  (설정 파일이 무한정 커지지 않도록).
- 기존에 "이 폴더에만 적용"으로 저장해 둔 값은 그대로 유효하다(같은 저장소를 쓴다).
- **정렬 옵션도 같은 규칙으로 폴더별 저장한다** — 폴더에서 정렬을 바꾸면 그 폴더에만 남는다.
- 쌓인 폴더별 설정은 설정 화면의 **"폴더별 보기 설정 모두 초기화"** 로 한 번에 지운다.

## 9. 설정 저장 · 호환성

- ⚠️ **보기 모드 enum 순서**: SharedPreferences에 **enum 이름이 아니라 ordinal(정수)** 로 저장된다
  ([SettingLiveDatas.kt:239](../../app/src/main/java/me/zhanghai/android/files/settings/SettingLiveDatas.kt#L239)).
  `MEDIA`는 반드시 **맨 뒤**에 추가한다(LIST=0, GRID=1, MEDIA=2).
  중간에 끼워 넣으면 기존 사용자의 저장된 설정이 다른 모드로 뒤바뀐다.
- ⚠️ **정렬 기준 enum 순서**: `FileSortOptions`는 `@Parcelize`로 직렬화되어 저장된다.
  `By.MEDIA_CREATED`도 **맨 뒤**에 추가한다(NAME=0, TYPE=1, SIZE=2, LAST_MODIFIED=3, MEDIA_CREATED=4).
- 기존 사용자의 전역 기본 보기 모드·정렬 값은 변경하지 않는다.
- 체크박스 제거로 `FileViewSortPathSpecificLiveData`의 역할이 바뀐다(§7.2). 저장 형식은 그대로다.

## 10. 성능 · 접근성 · 그 밖

**성능**

- 사진 500장 폴더에서 스크롤이 끊기지 않아야 한다.
- 열 수가 늘어난 만큼 화면에 동시에 보이는 썸네일이 바둑판 대비 2~3배가 된다.
  썸네일은 기존 Coil 경로를 그대로 쓰되, 화면 밖으로 나간 요청은 취소되어야 한다.
- 생성 시각은 1차 로딩에 포함되므로(§5.5) **폴더 진입 시간에 더해진다.** 기존과 마찬가지로
  백그라운드 스레드에서 돌아 UI는 막히지 않지만, 진행 표시가 보이는 시간이 그만큼 길어진다.
  두 번째 방문부터는 캐시로 사실상 0이다.
- 목표치: 사진 500장 폴더에서 **진입 즉시 mtime 순으로 표시**되고, 생성 시각 정렬은 백그라운드에서 완료된다.
  §5.7 실측(파일당 ~300바이트)을 근거로, 500개면 총 읽기량이 150KB 수준이다.

**접근성**

- 파일 이름이 화면에 없으므로 각 타일의 `contentDescription`에 **파일 이름**을 넣고,
  가능하면 "사진/동영상" 종류도 함께 읽히게 한다.
- `⋮` 버튼의 터치 타깃은 48dp 이상 유지. 4열 기준 타일 한 변이 약 90~100dp이므로
  아이콘은 24dp로 두고 히트 영역만 넓힌다.

**그 밖**

- **빠른 스크롤(fast scroll)** 유지. 미디어 생성 시각 정렬일 때 팝업에는 날짜를 보여준다.
  이름이 안 보이는 모드라 위치 파악의 유일한 단서다.
- **빈 상태**: 폴더에 사진·동영상도 하위 폴더도 없으면 "표시할 미디어가 없습니다" 안내를 띄운다.
- **검색 결과 화면**에도 미디어 모드를 적용한다.
- **파일 선택기(Pick) 모드**에서도 미디어 모드를 허용한다. 다른 앱이 사진 첨부를 요청했을 때
  특히 유용하다. 선택 규칙(단일/다중, MIME 필터)은 기존 로직 그대로.
- **화면 회전·창 크기 변경** 시 열 수를 다시 계산한다.

## 12. 수용 기준 (Acceptance Criteria)

1. 정렬 메뉴에 "미디어" 보기 항목과 "미디어 생성 시각" 정렬 항목이 보이고, "이 폴더에만 적용"은 사라졌다.
2. 미디어 모드에서 사진·동영상·폴더만 정사각형 타일로 표시되고, 타일 사이 간격이 없다.
3. 미디어 타일에는 이름이 없고, 폴더 타일에는 이름이 1줄 표시된다.
4. Pixel 8 세로에서 4열, 가로로 돌리면 열 수가 늘어난다.
5. 각 타일 우상단 `⋮`를 누르면 기존 항목 메뉴가 그대로 뜬다. 동영상 타일에는 ▶ 표시가 있다.
6. 롱프레스로 선택 모드에 들어가고, 선택된 타일이 시각적으로 구분된다.
7. 미디어 모드에서 정렬 기준은 "미디어 생성 시각"으로 고정되고 나머지 기준은 흐리게 표시된다.
   오름/내림차순은 바꿀 수 있다.
8. 미디어 모드로 폴더를 열면 **맨 아래(가장 최근 미디어)** 가 보이는 상태로 시작한다.
   내림차순으로 바꾸면 맨 위에서 시작한다.
9. **`/sdcard/SwingTestData` 검증**: `.mov` 파일들은 촬영 메타데이터가 전부
   2026-08-18 05:46로 뭉쳐 있지만(§5.3), 정렬 결과는 **2026-04-11 → 2026-08-19 순서**로
   흩어져야 한다(§5.4의 `min()` 규칙이 동작한다는 뜻).
10. 폴더 A에서 미디어 모드를 고르면 폴더 A만 미디어로 열리고, 폴더 B는 원래 모드 그대로다.
11. 앱을 껐다 켜도 폴더별 보기 모드가 유지되고, 기존 사용자가 업데이트해도 원래 모드가 그대로다.
12. 미디어가 없는 폴더에서 빈 상태 안내가 뜬다.
13. 사진 500장 규모에서 폴더 진입이 체감상 막히지 않는다.

| D5 | 검색 결과에도 적용 | **적용** |
| D6 | 파일 선택기(Pick) 모드에도 적용 | **적용**. Pick 모드 = 다른 앱이 첨부용 파일을 골라달라고 요청했을 때 뜨는 화면 |
| D7 | 메뉴 라벨 | **"미디어" / "Media"** (내부 이름도 `MEDIA`) |
| D8 | 폴더별 보기 모드 방식 | **"이 폴더에만 적용" 체크박스 제거.** 보기 모드는 항상 폴더별로 기억 (§7.2) |
| D9 | 생성 시각 취득 전략 | **파일에서 직접 읽기.** MediaStore는 주요 폴더에 `.nomedia`를 넣을 예정이라 쓸 수 없다 (§5.2). 이미지=EXIF, 동영상=경량 `mvhd` 파싱, 실패 시 `MediaMetadataRetriever` 폴백. 백그라운드 + 영구 캐시 (§5.5) |
| D10 | 파일시스템 생성 날짜를 쓸 것인가 | **쓸 수 없다** — 앱이 mtime으로 채우고, 안드로이드가 btime을 안 주고, 줘도 복사 시각이라 무의미 (§5.1). 대신 `min(메타데이터, mtime)` 규칙 채택 (§5.4) |
| D10-b | 재정렬 시 스크롤 재조정 | **해당 없음** — D15로 재정렬 자체가 사라짐 |
| D11 | 미디어 모드 정렬 제한 | 기준은 **미디어 생성 시각으로 고정**, 이름·종류·크기·수정시각은 흐리게. 오름/내림만 변경 가능 |
| D12 | 기본 정렬 방향 | **오름차순 + 진입 시 맨 아래(최신)로 스크롤** |
| D13 | 정렬 옵션도 폴더별 저장 | **폴더별로 저장한다.** 보기 모드와 같은 규칙(§7.2) |
| D14 | 폴더별 설정 초기화 수단 | 설정 화면에 **"폴더별 보기 설정 모두 초기화"** 항목 추가. 폴더별 개별 해제 UI는 만들지 않는다 |
